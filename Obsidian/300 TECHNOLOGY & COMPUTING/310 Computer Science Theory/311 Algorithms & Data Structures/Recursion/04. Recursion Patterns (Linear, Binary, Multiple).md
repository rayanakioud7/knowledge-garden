# Recursion Patterns (Linear, Binary, Multiple)

> [!info] Definitions & Properties
> Recursive algorithms are classified by the maximum number of recursive invocations initiated from a single execution frame:
> * **Linear Recursion**: Each invocation makes at most one recursive call.
> * **Binary Recursion**: An invocation makes two recursive calls.
> * **Multiple Recursion**: An invocation may make three or more recursive calls.
> 
> 

---

## 1. Linear Recursion

In linear recursion, each execution step initiates at most one recursive subproblem. The recursion trace forms a single sequential chain of activation records.

> [!note] Structural vs. Asymptotic Terminology
> The term "linear" describes the linear chain structure of the recursion trace, not the algorithm's asymptotic complexity. For example, binary search (see Section 4.1.3) is an instance of linear recursion that executes in $O(\log n)$ time.

### Summing Elements Recursively

To sum an array $S$ of $n$ numbers, define the sum of $n = 0$ elements as $0$, and for $n > 0$, add the last element $S[n - 1]$ to the recursive sum of the first $n - 1$ elements.

> [!NOTE] Figure 4.9
> ![[Pasted image 20260907204816.png|center]]

```python
def linear_sum(S, n):
    """Return the sum of the first n numbers of sequence S."""
    if n == 0:
        return 0
    else:
        return linear_sum(S, n - 1) + S[n - 1]

```

> [!NOTE] Figure 4.10
> ![[Pasted image 20260907204848.png|center]]

Computing `linear_sum(S, n)` requires $n + 1$ function calls. With $O(1)$ operations per activation, the algorithm executes in $O(n)$ time and requires $O(n)$ auxiliary space to maintain $n + 1$ simultaneous stack frames.

### Reversing a Sequence

A sequence $S$ of length $n$ is reversed by swapping its first and last elements, then recursively reversing the remaining inner slice $S[\text{start} + 1 : \text{stop} - 1]$.

```python
def reverse(S, start, stop):
    """Reverse elements in implicit slice S[start:stop]."""
    if start < stop - 1:                                # at least 2 elements
        S[start], S[stop - 1] = S[stop - 1], S[start]  # swap first and last
        reverse(S, start + 1, stop - 1)                 # recur on rest

```

> [!NOTE] Figure 4.11
> ![[Pasted image 20260907204920.png|center]]

The recursion terminates under two implicit base cases:

* $\text{start} == \text{stop}$: Implicit slice is empty ($n$ is even).
* $\text{start} == \text{stop} - 1$: Implicit slice contains one element ($n$ is odd).

The interval $\text{stop} - \text{start}$ decreases by $2$ at each step. The function terminates after $1 + \lfloor n / 2 \rfloor$ invocations, yielding $O(n)$ running time and $O(n)$ call-stack space.

### Computing Powers

The power function $x^n$ for an integer $n \ge 0$ can be computed using two distinct recursive formulations:

#### 1. Trivial Linear Formulation

$$x^n = \begin{cases} 1 & \text{if } n = 0 \\ x \cdot x^{n-1} & \text{otherwise} \end{cases}$$

```python
def power(x, n):
    """Compute the value x**n for integer n."""
    if n == 0:
        return 1
    else:
        return x * power(x, n - 1)

```

This implementation decrements $n$ by $1$ per call, running in $O(n)$ time and using $O(n)$ stack space across $n + 1$ activation records.

#### 2. Repeated Squaring Formulation

Using integer division $k = \lfloor n / 2 \rfloor$:

$$x^n = \begin{cases} 1 & \text{if } n = 0 \\ \left(x^{\lfloor n/2 \rfloor}\right)^2 & \text{if } n > 0 \text{ is even} \\ x \cdot \left(x^{\lfloor n/2 \rfloor}\right)^2 & \text{if } n > 0 \text{ is odd} \end{cases}$$

```python
def power(x, n):
    """Compute the value x**n for integer n."""
    if n == 0:
        return 1
    else:
        partial = power(x, n // 2)          # rely on truncated division
        result = partial * partial
        if n % 2 == 1:                      # if n is odd, include factor of x
            result *= x
        return result

```

> [!NOTE] Figure 4.12
> ![[Pasted image 20260907205025.png|center]]

> [!warning] Avoiding Redundant Branching
> Computing `power(x, n // 2) * power(x, n // 2)` without caching intermediate results creates two identical recursive branches, degrading performance back to $O(n)$ time.

Each recursive call halves the exponent $n$, limiting the total number of activations to $1 + \lfloor \log_2 n \rfloor$. The running time drops to $O(\log n)$, and maximum call-stack depth drops to $O(\log n)$.

## 2. Binary Recursion

In binary recursion, an execution frame initiates two recursive subproblems. Examples include `draw_interval` (see Section 4.1.2) and `bad_fibonacci` (see Section 4.3).

### Binary Summation

To sum elements in $S[\text{start}:\text{stop}]$, partition the range into two equal sub-intervals at $\text{mid} = \lfloor (\text{start} + \text{stop}) / 2 \rfloor$, recursively sum both halves, and return their addition.

```python
def binary_sum(S, start, stop):
    """Return the sum of the numbers in implicit slice S[start:stop]."""
    if start >= stop:                                   # zero elements in slice
        return 0
    elif start == stop - 1:                             # one element in slice
        return S[start]
    else:                                               # two or more elements
        mid = (start + stop) // 2
        return binary_sum(S, start, mid) + binary_sum(S, mid, stop)

```

### Linear Sum vs. Binary Sum

| Property | `linear_sum` (Code Fragment 4.9) | `binary_sum` (Code Fragment 4.13) |
| --- | --- | --- |
| **Recursion Structure** | Linear (1 call per frame) | Binary (2 calls per internal frame) |
| **Total Invocations** | $n + 1$ calls | $2n - 1$ calls (for $n$ a power of 2) |
| **Time Complexity** | $O(n)$ | $O(n)$ |
| **Maximum Stack Depth** | $n + 1$ activation frames | $1 + \lceil \log_2 n \rceil$ activation frames |
| **Space Complexity** | $O(n)$ | $O(\log n)$ |

## 3. Multiple Recursion

Multiple recursion generalizes binary recursion: a single activation frame may spawn three or more recursive calls. The file-system traversal algorithm `disk_usage` (see Section 4.1.4) uses multiple recursion, generating calls equal to the number of directory children.

### Combinatorial Summation Puzzles

Summation puzzles require assigning unique digits ($0, 1, \dots, 9$) to letters such that an arithmetic identity holds:

$$\begin{aligned} \text{pot} + \text{pan} &= \text{bib} \\ \text{dog} + \text{cat} &= \text{pig} \\ \text{boy} + \text{girl} &= \text{baby} \end{aligned}$$

To solve puzzles by exhaustive enumeration, generate all $k$-length ordered subsets from a universe $U$ without repetition.

```python
def PuzzleSolve(k, S, U):
    """Enumerate all k-length extensions to sequence S using elements of set U."""
    for e in list(U):
        S.append(e)
        U.remove(e)                                     # e is now being used
        if k == 1:
            # test whether S solves the puzzle
            if "S solves puzzle":
                print("Solution found:", S)
        else:
            PuzzleSolve(k - 1, S, U)                    # recursive call
        S.pop()                                         # remove e from end of S
        U.add(e)                                        # add e back to unused set U

```

### Complexity Analysis

For a universe $U$ of size $m = \vert{}U\vert{}$, an initial call `PuzzleSolve(k, S, U)` generates a tree where:

* Level 0 branches $m$ times.
* Level 1 branches $m - 1$ times.
* Level $k - 1$ terminates the recursion.

The total number of candidate sequences evaluated is the permutation count:

$$P(m, k) = \frac{m!}{(m - k)!} = m \cdot (m - 1) \cdots (m - k + 1)$$
