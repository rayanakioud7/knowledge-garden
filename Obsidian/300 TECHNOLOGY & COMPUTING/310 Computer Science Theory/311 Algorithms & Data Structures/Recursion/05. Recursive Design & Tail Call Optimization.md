# Recursive Design and Eliminating Tail Recursion

> [!info] Definitions & Properties
> Recursive design structures an algorithm into base cases and self-similar subproblems. Tail recursion occurs when the recursive call is the final operation performed within a function, allowing execution without accumulating activation records after the call returns.

---

## 1. Designing Recursive Algorithms

A standard recursive algorithm consists of two mandatory components:

* **Test for base cases**: Evaluate one or more stopping conditions that execute nonrecursively. Every execution path must eventually terminate at a base case.
* **Recur**: If a base case is not met, perform one or more recursive calls that make strict progress toward a base case.

### Parameterizing Recursion

Subproblems often require different boundaries than the original caller specifies. Reparameterizing the function signature allows tracking subproblem state without copying data.

| Function              | Public Interface              | Recursive Signature                      | Reparameterization Purpose                                                     |
| --------------------- | ----------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------ |
| **Binary Search**     | `binary_search(data, target)` | `binary_search(data, target, low, high)` | Demarcates sublists by index boundaries; avoids $O(n)$ list slicing copies.    |
| **Sequence Reversal** | `reverse(S)`                  | `reverse(S, start, stop)`                | Bounds the active slice between `start` and `stop - 1`.                        |
| **Linear Sum**        | `linear_sum(S)`               | `linear_sum(S, n)`                       | Tracks the prefix length $n$ to sum.                                           |
| **Binary Sum**        | `binary_sum(S)`               | `binary_sum(S, start, stop)`             | Defines interval boundaries for divide-and-conquer splitting.                  |
| **Fibonacci**         | `fibonacci(n)`                | `good_fibonacci(n)`                      | Strengthens return type to a pair $(F_n, F_{n-1})$ to prevent duplicate calls. |

> [!note] Interface Encapsulation
> Exposing low-level index parameters (such as `low` and `high`) clutters the public interface. A clean design exposes a user-friendly public function that delegates execution to a nonpublic recursive utility function containing the required parameters.

## 2. Eliminating Tail Recursion

> [!info] Definitions & Properties
> A recursive call is tail recursive if it is the very last operation executed by the enclosing function, and its return value is immediately returned to the caller. Tail recursion must be linear recursion.

General recursion can be made iterative by explicitly managing a stack data structure (see Section 6.1). However, tail recursion can be eliminated entirely without auxiliary memory.

### Tail Recursive vs. Non-Tail Linear Recursion

| Function         | Final Operation                          | Tail Recursive? | Reason                                                                |
| ---------------- | ---------------------------------------- | --------------- | --------------------------------------------------------------------- |
| `binary_search`  | `return binary_search(...)`              | **Yes**         | Result is returned directly without further computation.              |
| `reverse`        | `reverse(...)`                           | **Yes**         | Final statement executes the recursive call; no pending operations.   |
| `factorial`      | `return n * factorial(n - 1)`            | **No**          | Pending multiplication operation after the recursive call returns.    |
| `linear_sum`     | `return linear_sum(S, n - 1) + S[n - 1]` | **No**          | Pending addition operation after the recursive call returns.          |
| `good_fibonacci` | `(a, b) = good_fibonacci(n - 1)`         | **No**          | Constructs and returns new tuple `(a + b, a)` after the call returns. |

### Mechanical Conversion Pattern

To eliminate tail recursion mechanically:

1. Enclose the function body in a `while` loop.
2. Replace the base-case termination condition with its logical inverse as the loop condition.
3. Replace each recursive call by reassigning local loop variables to the arguments of that call.

## 3. Iterative Implementations

### Iterative Binary Search

Converting recursive `binary_search` (Section 4.1.3, Code Fragment 4.3) replaces the base case `low > high` with the loop condition `while low <= high:`. Parameter updates replace recursive function invocations.

```python
def binary_search_iterative(data, target):
    """Return True if target is found in the given Python list."""
    low = 0
    high = len(data) - 1
    while low <= high:
        mid = (low + high) // 2
        if target == data[mid]:
            return True                         # found a match
        elif target < data[mid]:
            high = mid - 1                      # only consider values left of mid
        else:
            low = mid + 1                       # only consider values right of mid
    return False                                # loop ended without success

```

### Iterative Sequence Reversal

Converting recursive `reverse` (Section 4.4.1, Code Fragment 4.10) updates `start` and `stop` iteratively within a loop until fewer than two elements remain.

```python
def reverse_iterative(S):
    """Reverse elements in sequence S."""
    start, stop = 0, len(S)
    while start < stop - 1:
        S[start], S[stop - 1] = S[stop - 1], S[start]  # swap first and last
        start, stop = start + 1, stop - 1              # narrow the range

```

### Complexity: Recursive vs. Iterative Comparison

Converting tail-recursive algorithms to iterative loops preserves time complexity while eliminating call-stack memory overhead.

| Algorithm             | Implementation                 | Time Complexity | Auxiliary Space (Call Stack)   |
| --------------------- | ------------------------------ | --------------- | ------------------------------ |
| **Binary Search**     | Recursive (Code Fragment 4.3)  | $O(\log n)$     | $O(\log n)$ activation records |
|                       | Iterative (Code Fragment 4.15) | $O(\log n)$     | $O(1)$ memory                  |
| **Sequence Reversal** | Recursive (Code Fragment 4.10) | $O(n)$          | $O(n)$ activation records      |
|                       | Iterative (Code Fragment 4.16) | $O(n)$          | $O(1)$ memory                  |

> [!note] Non-Tail Recursion Iteration
> Non-tail linear recursions can also be implemented iteratively with minimal state. For example, computing factorials, summing arrays, or calculating Fibonacci numbers via generators (see Section 1.8) runs in $O(n)$ time using only $O(1)$ auxiliary space.
