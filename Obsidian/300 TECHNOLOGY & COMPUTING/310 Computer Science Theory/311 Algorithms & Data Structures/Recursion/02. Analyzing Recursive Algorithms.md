# Analyzing Recursive Algorithms

> [!info] Definitions & Properties
> To analyze the running time of a recursive algorithm, account for the primitive operations executed within each individual activation frame. The overall running time is the sum of operations performed across all activations in the recursion trace.

---

## 1. Activation Accounting Framework

Analyzing a recursive function requires determining two quantities:

1. The total number of recursive invocations (activation frames).
2. The number of primitive operations performed within each activation frame (excluding subsequent recursive calls).

$$\text{Total Operations} = \sum_{\text{all activations } A} \text{Operations}(A)$$

---

## 2. Factorial Function Analysis

Computing `factorial(n)` (Section 4.1.1, Code Fragment 4.1) begins with parameter $n$ and decrements by 1 until reaching the base case $0$.

| Metric                  | Analysis                                                                               | Complexity |
| ----------------------- | -------------------------------------------------------------------------------------- | ---------- |
| **Total Activations**   | $n + 1$ frames (`factorial(n)` down to `factorial(0)`)                                 | $O(n)$     |
| **Work per Activation** | Constant number of primitive operations (condition check, subtraction, multiplication) | $O(1)$     |
| **Total Running Time**  | $(n + 1) \cdot O(1)$                                                                   | $O(n)$     |

## 3. English Ruler Output Analysis

Section 4.1.2 defines `draw_interval(c)`, where $c$ denotes the central tick length. The overall work is proportional to the total number of lines drawn.

> [!info] Proposition 4.1
> For $c \ge 0$, a call to `draw_interval(c)` results in precisely $2^c - 1$ lines of output.

### Proof by Induction (see Section 3.4.3)

* **Base Case ($c = 0$):** `draw_interval(0)` executes no calls to `draw_line`.
$$2^0 - 1 = 1 - 1 = 0 \text{ lines}$$


* **Inductive Step ($c > 0$):** `draw_interval(c)` executes two calls to `draw_interval(c - 1)` and one call to `draw_line(c)`. Assuming the claim holds for $c - 1$:

$$\text{Lines}(c) = 1 + 2 \cdot (2^{c-1} - 1) = 1 + 2^c - 2 = 2^c - 1$$



> [!note] Recurrence Relation
> The recurrence relation for the line count is $T(c) = 2T(c - 1) + 1$ with $T(0) = 0$. Solving this recurrence yields an exponential running time of $O(2^c)$ (see Section 12.2.4).

## 4. Binary Search Analysis

Binary search (Section 4.1.3, Code Fragment 4.3) searches a sorted sequence of $n$ elements by halving the candidate range at each invocation.

> [!info] Proposition 4.2
> The binary search algorithm runs in $O(\log n)$ time for a sorted sequence with $n$ elements.

### Proof & Candidate Interval Bounds

Let the number of candidate entries be $\text{high} - \text{low} + 1$. With each recursive invocation, the midpoint index $\text{mid} = \lfloor (\text{low} + \text{high}) / 2 \rfloor$ reduces the search space:

$$\begin{aligned} (\text{mid} - 1) - \text{low} + 1 &= \left\lfloor \frac{\text{low} + \text{high}}{2} \right\rfloor - \text{low} \le \frac{\text{high} - \text{low} + 1}{2} \\ \text{high} - (\text{mid} + 1) + 1 &= \text{high} - \left\lfloor \frac{\text{low} + \text{high}}{2} \right\rfloor \le \frac{\text{high} - \text{low} + 1}{2} \end{aligned}$$

| Recursive Stage | Maximum Remaining Candidates |
| --- | --- |
| Initial invocation ($j = 0$) | $n$ |
| After Call 1 ($j = 1$) | $n / 2$ |
| After Call 2 ($j = 2$) | $n / 4$ |
| After Call $j$ | $n / 2^j$ |

In the worst-case (unsuccessful search), recursion terminates when candidate entries drop below 1:

$$\frac{n}{2^r} < 1 \implies 2^r > n \implies r > \log n$$

The maximum number of recursive calls is:

$$r = \lfloor \log n \rfloor + 1$$

Each call executes $O(1)$ operations, yielding an overall running time of $O(\log n)$.

## 5. File System Disk Usage Analysis

The `disk_usage` algorithm (Section 4.1.4, Code Fragment 4.5) computes cumulative disk usage for $n$ file-system entries.

> [!info] Total Activation Invocations
> Exactly $n$ recursive calls to `disk_usage` occur. Each entry $e$ is encountered exactly once inside the `for` loop of its unique parent directory.

### Global Counting Argument (Amortized Analysis)

A superficial bound assumes each directory can contain up to $n - 1$ entries, leading to a loose estimate of $O(n)$ work per call $\times n$ calls = $O(n^2)$ time.

The tight upper bound is established by analyzing total loop iterations across the entire execution:

| Operation Category | Scope Across Entire Execution | Aggregate Running Time |
| --- | --- | --- |
| **Outside Loop** | Executed once per activation frame ($n$ calls total, each doing $O(1)$ work) | $O(n)$ |
| **Inside Loop** | Iterates over each directory child; exactly $n - 1$ total iterations across all frames | $O(n)$ |
| **Total Running Time** | $\sum \text{Outside Loop} + \sum \text{Inside Loop}$ | $O(n)$ |

> [!note] Amortization and Tree Traversals
> Evaluating the cumulative work of loop iterations across all recursive frames rather than assuming the worst case for each individual invocation is an amortized argument (see Section 5.3). The file-system hierarchy is a tree data structure, and `disk_usage` performs an $O(n)$ tree traversal (see Chapter 8, Section 8.4).

## 6. Algorithmic Complexity Comparison

| Algorithm | Input Parameter / Size Metric | Total Recursive Activations | Operations per Activation Frame | Total Asymptotic Running Time |
| --- | --- | --- | --- | --- |
| `factorial(n)` | Integer $n$ | $n + 1$ | $O(1)$ | $O(n)$ |
| `draw_interval(c)` | Tick length $c$ | $2^{c+1} - 1$ | $O(1)$ | $O(2^c)$ |
| `binary_search` | Sequence length $n$ | $\le \lfloor \log n \rfloor + 1$ | $O(1)$ | $O(\log n)$ |
| `disk_usage` | Total file-system entries $n$ | $n$ | Variable (amortized $O(1)$) | $O(n)$ |
