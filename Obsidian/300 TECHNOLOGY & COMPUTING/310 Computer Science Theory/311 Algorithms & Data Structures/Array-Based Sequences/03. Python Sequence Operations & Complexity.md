# Python Sequence Operations & Complexity

> [!info] Definitions & Properties
> Python's built-in sequence classes (`list`, `tuple`, `str`) provide a variety of standard behaviors. Nonmutating behaviors do not change the underlying sequence and are supported by both `list` and `tuple`. Mutating behaviors alter the sequence contents and are exclusively supported by the mutable `list` class.
> 
> 

---

## 1. Nonmutating Operations (Lists & Tuples)

Tuples are typically more memory efficient than lists because their immutability negates the need for dynamic array surplus capacity. Both classes share identical asymptotic efficiencies for nonmutating operations.

### Table 5.3: Asymptotic Performance of Nonmutating Behaviors

Let $n, n_1, n_2$ be lengths of respective sequences. Let $k$ denote the index of the leftmost occurrence of a searched value (or $n$ if absent).

| Operation         | Syntax              | Running Time       | Explanation                                                     |
| ----------------- | ------------------- | ------------------ | --------------------------------------------------------------- |
| **Length**        | `len(data)`         | $O(1)$<br>         | Retrieves cached instance state variable.                       |
| **Index Access**  | `data[j]`           | $O(1)$             | Direct memory address calculation via offset.                   |
| **Index Lookup**  | `data.index(value)` | $O(k + 1)$<br>     | Iterates left-to-right until match is found.                    |
| **Containment**   | `value in data`     | $O(k + 1)$<br>     | Short-circuits loop immediately upon finding match.             |
| **Comparison**    | `data1 == data2`    | $O(k + 1)$         | Lexicographical evaluation stops at first mismatched index $k$. |
| **Slicing**       | `data[j:k]`         | $O(k - j + 1)$<br> | Instantiates a new sequence proportional to the slice length.   |
| **Concatenation** | `data1 + data2`     | $O(n_1 + n_2)$<br> | Creates a new sequence copying all elements from both operands. |
| **Repetition**    | `c * data`          | $O(cn)$<br>        | Creates a new sequence of total length $c \cdot n$.             |

## 2. Mutating Operations (Lists Only)

Mutating operations alter the structure or contents of a `list`. Operations that insert or delete elements may trigger an $O(n)$ dynamic array resize or require shifting subsequent elements in memory.

### Table 5.4: Asymptotic Performance of Mutating Behaviors

| **Operation**    | **Syntax**            | **Running Time** | **Explanation**                                                       |
| ---------------- | --------------------- | ---------------- | --------------------------------------------------------------------- |
| **Assignment**   | `data[j] = val`       | $O(1)$           | Replaces object reference at index $j$; no shifting required.         |
| **Append**       | `data.append(val)`    | $O(1)^*$         | Amortized cost; occasionally requires $O(n)$ reallocation.            |
| **Insert**       | `data.insert(k, val)` | $O(n - k + 1)^*$ | Amortized reallocation; shifts $n - k$ elements rightward.            |
| **Pop End**      | `data.pop()`          | $O(1)^*$         | Amortized; removes last element without shifting.                     |
| **Pop Index**    | `data.pop(k)`         | $O(n - k)^*$     | Amortized; shifts $n - k$ elements leftward to fill gap.              |
| **Delete Index** | `del data[k]`         | $O(n - k)^*$     | Same shifting mechanics as `pop(k)`.                                  |
| **Remove Value** | `data.remove(val)`    | $O(n)^*$         | Iterates up to index $k$ to find match, then shifts $n - k$ elements. |
| **Extend**       | `data1.extend(data2)` | $O(n_2)^*$       | Highly optimized amortized bulk append; resizes array at most once.   |
| **Reverse**      | `data.reverse()`      | $O(n)$           | Swaps $\lfloor n/2 \rfloor$ pairs in-place.                           |
| **Sort**         | `data.sort()`         | $O(n \log n)$    | Uses Timsort algorithm (hybrid merge/insertion sort).                 |

(Asterisk $*$ denotes an amortized running time bound.)

### Insertion Efficiency (Table 5.5)

Empirical testing confirms `insert(k, val)` execution time depends directly on the location of $k$:

* **Beginning ($k = 0$)**: Slowest ($\Omega(n)$); shifts all elements.


* **Middle ($k = n // 2$)**: Faster ($\Omega(n)$); shifts half the elements.


* **End ($k = n$)**: Fastest ($O(1)$ amortized); behaves identically to `append`.



### List Extension

While `data.extend(other)` and a `for` loop calling `data.append()` both run in proportional time, `extend` is significantly faster in practice:

1. Implemented natively in compiled C code, minimizing interpreter loop overhead.


2. Computes final capacity needed and performs at most one underlying array reallocation.

## 3. Python's String Class

Strings (`str`) are compact arrays of characters and are immutable.

### Naive String Concatenation Trap

Concatenating strings iteratively creates a new string instance per loop, leading to catastrophic quadratic $O(n^2)$ behavior:

```python
# WARNING: O(n^2) running time
letters = ''
for c in document:
    if c.isalpha():
        letters += c  # creates a new string instance each iteration

```

(Note: Some Python interpreters apply a runtime optimization if `letters` has no other references, temporarily mutating the string, but this behavior is not guaranteed).

### Optimal String Composition Methods

For guaranteed $O(n)$ execution, construct a temporary list of characters and use `"".join()`.

#### Method 1: List Construction

```python
temp = []
for c in document:
    if c.isalpha():
        temp.append(c)          # O(1) amortized
letters = ''.join(temp)         # O(n) final string composition

```

#### Method 2: List Comprehension

```python
letters = ''.join([c for c in document if c.isalpha()])

```

#### Method 3: Generator Expression (Most Memory Efficient)

```python
letters = ''.join(c for c in document if c.isalpha())

```
