> **One sentence summary:** Multi-head attention runs 8 independent self-attention operations in parallel — each learning to look for a different type of relationship between frames — then combines all 8 answers into a single rich representation.

---

## 1. The Problem With a Single Attention Head

In concept 11 you built one self-attention head. It worked. But it has a fundamental limitation.

A single softmax produces **one distribution** over the 64 frames. Frame 20 can only distribute its attention in one way across all other frames.

But sign language has **multiple simultaneous structures**:

```
Structure 1: Where is the hand relative to the face?
Structure 2: How fast is the hand moving?
Structure 3: What handshape is forming?
Structure 4: Are the eyebrows raised or furrowed?
Structure 5: When does the sign start and end?
```

A single attention head must try to capture all of these with one set of Q, K, V projections. It cannot. It will learn the most dominant pattern and ignore the rest.

Multi-head attention solves this by running **8 independent heads in parallel**, each free to specialise on a different structure.

---

## 2. The Intuition — 8 Specialists Working Simultaneously

Think of 8 different experts analysing the same sign video simultaneously:

```
Expert 1: "I will focus on hand location relative to body"
Expert 2: "I will focus on velocity and motion direction"  
Expert 3: "I will focus on handshape formation"
Expert 4: "I will focus on facial expression timing"
Expert 5: "I will focus on the boundary between preparation and core sign"
Expert 6: "I will focus on symmetry between left and right hand"
Expert 7: "I will focus on which frames to ignore (padding detection)"
Expert 8: "I will focus on overall temporal structure of the sign"
```

Each expert independently decides what to pay attention to.

Then you ask all 8 experts for their answer and **concatenate** their reports into one complete picture.

That is multi-head attention.

---

## 3. The Mechanics — How 8 Heads Work

### Step 1: Split into 8 heads

Your model dimension is $d_{\text{model}} = 256$.
You have $h = 8$ attention heads.
Each head gets:

$$d_k = \frac{d_{\text{model}}}{h} = \frac{256}{8} = 32 \text{ dimensions}$$

Each head $i$ has its own learned weight matrices:

$$\mathbf{W}^i_Q \in \mathbb{R}^{256 \times 32}, \quad
  \mathbf{W}^i_K \in \mathbb{R}^{256 \times 32}, \quad
  \mathbf{W}^i_V \in \mathbb{R}^{256 \times 32}$$

### Step 2: Each head computes its own attention

For head $i$:

$$\mathbf{Q}^i = \mathbf{H}^2 \mathbf{W}^i_Q \in \mathbb{R}^{64 \times 32}$$
$$\mathbf{K}^i = \mathbf{H}^2 \mathbf{W}^i_K \in \mathbb{R}^{64 \times 32}$$
$$\mathbf{V}^i = \mathbf{H}^2 \mathbf{W}^i_V \in \mathbb{R}^{64 \times 32}$$

$$\text{head}_i = \text{softmax}\!\left(\frac{\mathbf{Q}^i (\mathbf{K}^i)^\top}{\sqrt{32}} + \mathbf{M}\right)\mathbf{V}^i \in \mathbb{R}^{64 \times 32}$$

This is exactly the formula from concept 11 — but applied 8 times with 8 different weight matrices.

### Step 3: Concatenate all 8 outputs

$$\text{Concat}(\text{head}_1, \text{head}_2, \ldots, \text{head}_8) \in \mathbb{R}^{64 \times 256}$$

Each head produced $(64 \times 32)$. Concatenating 8 of them along the last dimension gives $(64 \times 256)$.

### Step 4: Final linear projection

$$\text{MultiHead}(\mathbf{H}^2) = \text{Concat}(\text{head}_1, \ldots, \text{head}_8)\, \mathbf{W}_O$$

Where $\mathbf{W}_O \in \mathbb{R}^{256 \times 256}$ is a learned output projection matrix.

This final projection mixes information from all 8 heads together, allowing the model to combine the specialists' reports into one coherent representation.

---

## 4. The Complete Formula

$$\text{MultiHead}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h)\, \mathbf{W}_O$$

$$\text{where} \quad \text{head}_i = \text{Attention}(\mathbf{H}^2 \mathbf{W}^i_Q,\ \mathbf{H}^2 \mathbf{W}^i_K,\ \mathbf{H}^2 \mathbf{W}^i_V)$$

$$\text{and} \quad \text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}} + \mathbf{M}\right)\mathbf{V}$$

## 5. Shape Transformations — The Complete Picture

```
Input: H² (64, 256)
              │
    ┌─────────┴─────────────────────────────┐
    │ Replicate H² to all 8 heads           │
    └─────────┬─────────────────────────────┘
              │
   ┌──────────┼──────────────────┐
   │          │          ...     │
 Head 1     Head 2           Head 8
(64,256)   (64,256)         (64,256)
   │ ×Wq,Wk,Wv               │ ×Wq,Wk,Wv
(64,32)   (64,32)           (64,32)
   │ attention                 │ attention
(64,32)   (64,32)           (64,32)
   │          │                 │
   └──────────┴─────────────────┘
              │ Concatenate
         (64, 256)   ← 8 × 32 = 256
              │
              │ × Wo (256×256)
              │
         (64, 256)
              │
           Output
```

The input and output shapes are identical: $(64, 256) \rightarrow (64, 256)$.

This is important. The Transformer layer does not change the shape of the data. It enriches the representation of each frame by incorporating information from all other frames.

## 6. A Concrete Worked Example

Let us trace one frame through two heads to see the difference.

**Setup:** Frame 20 (the core mouth motion in `DRINK`)

```
Frame 20 representation: h₂₀ ∈ ℝ²⁵⁶
(This is the 256-dimensional vector after the CNN block)
```

**Head 1 — specialised for hand position:**

```
Q¹₂₀ = h₂₀ × W¹_Q   →  q¹₂₀ encodes "looking for frames with hand near face"
K¹_j  = h_j × W¹_K  →  keys encode "what hand position does this frame have"

Attention weights for head 1:
  A¹[20, 5]  = 0.02   (Frame 5 has hand far from face — not relevant)
  A¹[20, 15] = 0.31   (Frame 15 has hand approaching face — highly relevant)
  A¹[20, 20] = 0.45   (Frame 20 itself — hand at face — most relevant)
  A¹[20, 35] = 0.18   (Frame 35 has hand leaving face — somewhat relevant)
  A¹[20, 55] = 0.00   (Padding — zeroed by mask)

head₁[20] = weighted sum of V¹_j vectors → rich "hand position context"
```

**Head 2 — specialised for motion velocity:**

```
Q²₂₀ = h₂₀ × W²_Q   →  q²₂₀ encodes "looking for frames with decelerating motion"
K²_j  = h_j × W²_K  →  keys encode "what velocity profile does this frame have"

Attention weights for head 2:
  A²[20, 5]  = 0.28   (Frame 5 has fast upward motion — highly relevant for context)
  A²[20, 15] = 0.38   (Frame 15 has decelerating motion — very relevant)
  A²[20, 20] = 0.22   (Frame 20 itself)
  A²[20, 35] = 0.12   (Frame 35 has fast downward motion — somewhat relevant)
  A²[20, 55] = 0.00   (Padding)

head₂[20] = weighted sum of V²_j vectors → rich "velocity context"
```

**After concatenation:**

```
[head₁[20] | head₂[20] | ... | head₈[20]]
 (32)         (32)               (32)
└─────────────────────────────────────────┘
               (256)

Frame 20 now contains:
  - hand position context from head 1
  - velocity context from head 2
  - handshape context from head 3
  - facial expression context from head 4
  ... and so on for all 8 heads
```

After the output projection $\mathbf{W}_O$, these 8 perspectives are mixed into a single $(256)$-dimensional vector that is richer than any single head could produce.

## 7. Why Not Just Use One Big Head?

A natural question: why not just use $d_k = 256$ instead of 8 heads of $d_k = 32$?

This is a fair question. Here is the technical answer and the intuitive answer.

**Technical answer:**

With $d_k = 256$ (one big head), the softmax operates on scores across 256 dimensions. It can learn one complex attention pattern. With 8 heads of $d_k = 32$, you have 8 independent softmax operations. Each produces its own complete distribution over all 64 frames.

The key word is **independent**. Head 2 cannot interfere with head 1 because they have completely separate weight matrices. They are forced to specialise differently because they are optimised by the same loss but through different parameter paths.

**Intuitive answer:**

One attention distribution cannot simultaneously say "pay most attention to frame 15" and "pay most attention to frame 5" — softmax forces a single distribution. But:
- Head 1 can say: "pay most attention to frame 15"
- Head 2 can say: "pay most attention to frame 5"
- Head 3 can say: "pay most attention to frame 30"

All simultaneously. One big head would have to compromise.

**Parameter count comparison:**

| Approach | Parameters |
|---|---|
| 1 head, $d_k = 256$ | $3 \times (256 \times 256) = 196{,}608$ |
| 8 heads, $d_k = 32$ | $8 \times 3 \times (256 \times 32) + 256 \times 256 = 262{,}144$ |

Multi-head attention has slightly more parameters, mostly in $\mathbf{W}_O$. But the qualitative difference — forced specialisation — is worth it.

## 8. Parameter Count in Your Model

Your model uses $h = 8$ heads, $d_{\text{model}} = 256$, $d_k = 32$.

For one Transformer layer, the multi-head attention module contains:

| Parameter | Size | Count |
|---|---|---|
| $\mathbf{W}^i_Q$ per head | $256 \times 32$ | 8 heads |
| $\mathbf{W}^i_K$ per head | $256 \times 32$ | 8 heads |
| $\mathbf{W}^i_V$ per head | $256 \times 32$ | 8 heads |
| $\mathbf{W}_O$ output | $256 \times 256$ | 1 |
| Biases | various | small |

Total per layer:
$$3 \times 8 \times (256 \times 32) + (256 \times 256) = 196{,}608 + 65{,}536 = 262{,}144 \text{ parameters}$$

Your model has 4 Transformer layers (in the base configuration), so multi-head attention contributes:

$$4 \times 262{,}144 \approx 1{,}048{,}576 \text{ parameters}$$

That is about 27% of the 3.86M total parameters in the base model.

## 9. The Padding Mask — How It Works Across 8 Heads

The padding mask $\mathbf{M}$ is applied **inside every head independently**.

Before softmax in each head, any column corresponding to a padding frame is set to $-\infty$. This means:

```
For all 8 heads:
  If frame j is padding:
    score(i, j) = -∞ for all frames i
    → after softmax: A[i, j] = 0 for all frames i

Padding frames contribute zero value to every output,
regardless of which head is computing.
```

This is what `src_key_padding_mask` does in PyTorch's `nn.MultiheadAttention`. You pass a boolean tensor where `True` means "this frame is padding — ignore it".

## 10. What Specialisation Actually Looks Like

Nobody tells the heads what to specialise in. It emerges from training. But visualising attention weights from trained sign language models reveals consistent patterns:

**Typically observed (not guaranteed):**

```
Some heads learn to attend to:
  → The beginning and end of the sign (boundary detection)
  → Frames with similar handshape regardless of time position
  → The peak motion frame from all surrounding frames
  → The dominant hand versus the non-dominant hand

Some heads become "garbage collectors":
  → They learn to attend mostly to the current frame itself
     (diagonal attention matrix)
  → These seem to act as a passthrough, preserving the
     original representation when global context is not needed
```

The fact that some heads become near-diagonal (attending mostly to themselves) is actually useful — it means the model can choose, per-frame, whether to incorporate global context or just use local information.

## 11. Connection to Your Model Architecture

In your `ASLTransformerV11`, multi-head attention appears inside `nn.TransformerEncoderLayer`, called as:

```python
encoder_layer = nn.TransformerEncoderLayer(
    d_model   = 512,    # scaled config
    nhead     = 8,      # 8 attention heads → d_k = 64
    dim_feedforward = 2048,
    dropout   = 0.3,
    activation = 'gelu',
    batch_first = True,
    norm_first  = True,  # Pre-LN: LayerNorm BEFORE attention
)
```

With the scaled architecture ($d_{\text{model}} = 512$):

$$d_k = \frac{512}{8} = 64 \text{ dimensions per head}$$

Each head's Q, K, V matrices are $512 \times 64$. The output matrix $\mathbf{W}_O$ is $512 \times 512$.

---

## 12. Pre-LayerNorm vs Post-LayerNorm

Your model uses `norm_first=True`. This means **LayerNorm is applied BEFORE** the attention operation, not after. This is called Pre-LN or Pre-Norm.

**Post-LN (original Transformer):**
$$\text{output} = \text{LayerNorm}(\mathbf{H}^2 + \text{MultiHead}(\mathbf{H}^2))$$

**Pre-LN (your model):**
$$\text{output} = \mathbf{H}^2 + \text{MultiHead}(\text{LayerNorm}(\mathbf{H}^2))$$

Pre-LN is more stable during training because the gradients flow through the residual connection without being modified by LayerNorm first. Research has shown Pre-LN converges faster and is less sensitive to learning rate choice. This is why almost all modern Transformers use it.

## 13. Summary

| Concept | Definition |
|---|---|
| **Number of heads** | $h = 8$ — 8 independent attention operations |
| **Dimension per head** | $d_k = d_{\text{model}} / h = 256/8 = 32$ (base) or $512/8 = 64$ (scaled) |
| **Per-head Q, K, V** | $\mathbf{H}^2 \mathbf{W}^i_Q$, etc. — different projection for each head |
| **Head output** | $(64, 32)$ — one head's attended representation |
| **Concatenation** | $(64, 256)$ — 8 heads joined along the feature dimension |
| **Output projection** | $\mathbf{W}_O$ mixes all heads' information |
| **Specialisation** | Each head learns different relationships — not programmed, emerges |
| **Padding mask** | Applied inside every head — padding columns receive zero attention |

## 14. The Full Equation — Every Symbol Explained

$$\boxed{\text{MultiHead}(\mathbf{H}^2) = \text{Concat}(\text{head}_1, \ldots, \text{head}_8)\, \mathbf{W}_O}$$

$$\text{head}_i = \text{softmax}\!\left(\frac{\mathbf{H}^2\mathbf{W}^i_Q\,(\mathbf{H}^2\mathbf{W}^i_K)^\top}{\sqrt{d_k}} + \mathbf{M}\right)\mathbf{H}^2\mathbf{W}^i_V$$

| Symbol | Shape | Meaning |
|---|---|---|
| $\mathbf{H}^2$ | $(64, 256)$ | Input: 64 frame representations after CNN |
| $\mathbf{W}^i_Q$ | $(256, 32)$ | Head $i$'s query projection |
| $\mathbf{W}^i_K$ | $(256, 32)$ | Head $i$'s key projection |
| $\mathbf{W}^i_V$ | $(256, 32)$ | Head $i$'s value projection |
| $d_k = 32$ | scalar | Dimension per head |
| $\sqrt{d_k}$ | scalar | Gradient stabilisation |
| $\mathbf{M}$ | $(64, 64)$ | Padding mask ($0$ or $-\infty$) |
| $\text{head}_i$ | $(64, 32)$ | One head's output |
| $\text{Concat}(\cdot)$ | $(64, 256)$ | 8 heads joined |
| $\mathbf{W}_O$ | $(256, 256)$ | Output projection |
| **Output** | $(64, 256)$ | Enriched frame representations |

## 15. What Comes Next

Multi-head attention produces $(64, 256)$ — the same shape as its input.

This output goes through:

1. **Residual connection** — add the original input back
2. **LayerNorm** — stabilise the values  
3. **Feed-Forward Block** — process each frame independently with a two-layer MLP (concept 13)
4. **Residual connection** — add again
5. **LayerNorm** — stabilise again

Together, attention + feed-forward + two residuals + two layer norms = one complete Transformer encoder layer.

Your model has 4 of these layers stacked (base config) or 6 (scaled config). Each layer refines the frame representations further, each time with access to the full global context of all 64 frames.
