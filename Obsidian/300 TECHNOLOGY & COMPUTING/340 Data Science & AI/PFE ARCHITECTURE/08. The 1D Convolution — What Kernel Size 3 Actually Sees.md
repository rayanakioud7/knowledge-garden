

> **One sentence summary:** A 1D convolution slides a small window
> of size 3 across the 64-frame sequence, at each position computing
> a weighted sum of 3 consecutive frames — learning to detect local
> temporal patterns like velocity, acceleration, and oscillation
> between adjacent frames.

---

## 1. Starting Point — What Enters the 1D-CNN

After the Linear Projection and LayerNorm, you have:

$$\mathbf{H}^{(0)} \in \mathbb{R}^{B \times T \times d_{\text{model}}}
= \mathbb{R}^{64 \times 64 \times 256}$$

- $B = 64$ — batch size (64 sign sequences)
- $T = 64$ — temporal frames
- $d_{\text{model}} = 256$ — learned features per frame

Think of this as a **sequence of 64 vectors**, each of length 256.
Each vector is one frame's learned representation — not raw
coordinates anymore, but 256 abstract features learned by the
projection.

```text
Frame  1: [f₁, f₂, f₃, ..., f₂₅₆]  ← 256 features
Frame  2: [f₁, f₂, f₃, ..., f₂₅₆]
Frame  3: [f₁, f₂, f₃, ..., f₂₅₆]
...
Frame 64: [f₁, f₂, f₃, ..., f₂₅₆]
```

---

## 2. The Problem — Why We Need a CNN at All

The Transformer (Stage 4) will handle long-range relationships
between frames — "what is happening at frame 5 compared to
frame 60?"

But the Transformer is **permutation-invariant**. Without
positional encoding, shuffling the frames would produce the same
output. Even with positional encoding, the Transformer computes
all pairwise frame relationships simultaneously — it does not
naturally focus on what is happening between **adjacent** frames.

Local motion — the velocity and acceleration of hands between
consecutive frames — is the most physically meaningful signal
for sign recognition. A sign is defined by how the hand **moves**,
not just where it is at each instant.

The 1D-CNN exists specifically to compute this local temporal
structure before the Transformer handles global structure.

**Analogy:** Imagine reading a sentence:

```text
"The cat sat on the mat"
```

A Transformer reads all words simultaneously and compares every
word to every other word. But to understand grammar, you first
need to notice that "cat" and "sat" are adjacent — that "cat"
is the subject performing "sat." Local adjacency matters.

For sign language, the 1D-CNN notices that frame 20 and frame 21
show the hand moving upward — that local adjacency is velocity.

## 3. The PyTorch Convention — Why We Transpose

PyTorch's `Conv1d` expects input shape:

$$\text{(Batch, Channels, Length)}$$

But your data is:

$$\text{(Batch, Time, Features)} = (64, 64, 256)$$

So before the CNN you transpose:

```python
x = x.transpose(1, 2)   # (64, 64, 256) → (64, 256, 64)
                         #  B   T   C       B   C    T
```

Now:
- **Channels** = 256 (the learned features — treated like image channels)
- **Length** = 64 (the time axis — treated like spatial width)

The convolution slides along the **time axis** (length=64),
treating the 256 features as parallel channels.

After the CNN you transpose back:

```python
x = x.transpose(1, 2)   # (64, 256, 64) → (64, 64, 256)
```

## 4. What One Convolutional Filter Does

A single convolutional filter of kernel size 3 is a weight
matrix of shape:

$$\mathbf{K} \in \mathbb{R}^{d_{\text{out}} \times d_{\text{in}} \times 3}
= \mathbb{R}^{256 \times 256 \times 3}$$

Wait — that is enormous. Let us simplify to understand one
**output channel** $k$ and one **input channel** $c$:

$$K_{k,c} \in \mathbb{R}^3 = [w_{-1},\ w_0,\ w_{+1}]$$

This tiny vector of 3 numbers is the kernel for output channel
$k$, applied to input channel $c$.

At time position $t$, this kernel produces one output value:

$$\text{out}_{k,c}(t) = w_{-1} \cdot h_c(t-1)
                       + w_0   \cdot h_c(t)
                       + w_{+1} \cdot h_c(t+1)$$

Where $h_c(t)$ is the value of input channel $c$ at frame $t$.

The full output at channel $k$, time $t$ sums over all input
channels:

$$\text{out}_k(t) = \sum_{c=1}^{256}
\left[ w_{k,c,-1} \cdot h_c(t-1)
     + w_{k,c,0}  \cdot h_c(t)
     + w_{k,c,+1} \cdot h_c(t+1) \right] + b_k$$

This is a weighted sum of **three consecutive frames**,
across **all 256 input channels**, producing **one output value**
at position $t$ for output channel $k$.

---

## 5. The Sliding Window — Frame by Frame

The kernel slides across all 64 time positions:

```text
Input sequence (simplified to 1 channel, 6 frames):

Frame:  [  1    2    3    4    5    6  ]
Value:  [0.2  0.5  0.8  0.6  0.3  0.1]

Kernel: [w₋₁, w₀, w₊₁] = [-0.5, 1.0, 0.5]
```

**At position t=2 (frame 2):**
```text
out(2) = w₋₁ × frame(1) + w₀ × frame(2) + w₊₁ × frame(3)
       = (-0.5)(0.2) + (1.0)(0.5) + (0.5)(0.8)
       = -0.10 + 0.50 + 0.40
       = 0.80
```

**At position t=3 (frame 3):**
```text
out(3) = (-0.5)(0.5) + (1.0)(0.8) + (0.5)(0.6)
       = -0.25 + 0.80 + 0.30
       = 0.85
```

**At position t=4 (frame 4):**
```text
out(4) = (-0.5)(0.8) + (1.0)(0.6) + (0.5)(0.3)
       = -0.40 + 0.60 + 0.15
       = 0.35
```

The kernel slides across all positions producing one output
value per position. The output sequence has the same length
as the input (because `padding=1` adds one zero on each end).

## 6. What the Kernel Actually Learns — The Physics

Here is the deep part. The kernel weights $[w_{-1}, w_0, w_{+1}]$
are learned during training. What patterns do they converge to?

### Kernel that detects velocity (1st derivative):

$$\mathbf{K}_{\text{velocity}} = [-1,\ 0,\ +1]$$

$$\text{out}(t) = (+1) \cdot h(t+1) + (0) \cdot h(t) + (-1) \cdot h(t-1)
= h(t+1) - h(t-1)$$

This is the **central difference approximation** of the first
derivative — the rate of change. If the hand moves from position
0.2 to 0.8 in two frames, this kernel outputs 0.6 — a strong
positive velocity signal.

### Kernel that detects acceleration (2nd derivative):

$$\mathbf{K}_{\text{accel}} = [+1,\ -2,\ +1]$$

$$\text{out}(t) = h(t+1) - 2h(t) + h(t-1)$$

This is the **second difference** — the rate of change of the
rate of change. If the hand is decelerating (moving fast then
slow), this kernel fires strongly.

### Kernel that detects a local peak:

$$\mathbf{K}_{\text{peak}} = [-1,\ +2,\ -1]$$

Fires strongly when $h(t)$ is larger than both its neighbors
— detecting the apex of a hand movement.

### Kernel that detects static hold:

$$\mathbf{K}_{\text{hold}} = [+1,\ +1,\ +1]$$

Fires strongly when three consecutive frames have similar
high values — detecting intentional stillness (a valid ASL
phoneme).

**The model does not know these templates in advance.**
It discovers them through training by learning which local
temporal patterns are most useful for distinguishing between
250 ASL signs. The weights converge to something resembling
these derivatives because that is genuinely what distinguishes
signs at the local level.

> [!NOTE] Important: Convolution vs Cross-Correlation
> 
> In pure mathematics, convolution flips the kernel before sliding:
> $(f * k)(t) = \sum_i k(i) \cdot f(t-i)$.
> PyTorch `Conv1d` computes **cross-correlation** instead —
> no flip: $(f \star k)(t) = \sum_i k(i) \cdot f(t+i)$.
> 
> In practice this distinction is irrelevant because the kernels
> are learned during training. If the mathematically correct
> velocity kernel is $[-1, 0, +1]$, PyTorch will simply learn
> $[+1, 0, -1]$ instead — the two are equivalent up to a sign
> flip. Every deep learning framework uses cross-correlation
> and calls it convolution by convention.

## 7. Two Layers — Why Stack Two Convolutions?

Your model has two consecutive Conv1d layers:

```python
self.cnn_block = nn.Sequential(
    nn.Conv1d(256, 256, kernel_size=3, padding=1),
    nn.GELU(),
    nn.Dropout(0.3),
    nn.Conv1d(256, 256, kernel_size=3, padding=1),
    nn.GELU(),
    nn.Dropout(0.3),
)
```

### The Receptive Field Argument

The **receptive field** is how many original input frames
one output unit depends on.

**After Conv1 (kernel=3):**
Each output frame sees 3 input frames:

```text
Output frame t depends on: input frames [t-1, t, t+1]
Receptive field = 3 frames
```

**After Conv2 (kernel=3 applied to Conv1 output):**
Each Conv2 output depends on 3 Conv1 outputs.
Each Conv1 output depends on 3 original inputs.
Therefore:

```text
Output frame t depends on: input frames [t-2, t-1, t, t+1, t+2]
Receptive field = 5 frames
```

Two stacked size-3 convolutions give an effective receptive
field of 5 frames — without increasing kernel size.

### The Hierarchy Argument

Layer 1 detects **simple local patterns**:
- "Hand moved upward between frame $t-1$ and $t+1$"
- "Hand is stationary at frame $t$"

Layer 2 detects **patterns of patterns**:
- "Hand moved upward THEN decelerated"
- "Hand was stationary THEN started moving"

This is the same principle as deep CNNs in image recognition:
Layer 1 detects edges. Layer 2 detects corners (edges of edges).
Layer 3 detects shapes (corners of edges of edges).

For your sign sequences:
Layer 1 detects velocity
Layer 2 detects acceleration and motion phase transitions

## 8. The Residual Connection — Why We Add the Input Back

After both conv layers, your code does:

```python
residual = x            # save input before CNN
x = self.cnn_block(x)  # apply both conv layers
x = self.cnn_norm(x + residual)  # ADD INPUT BACK
```

The output is:

$$\mathbf{H}^{(1)} = \text{LayerNorm}(\text{Conv}_2(\text{Conv}_1(\mathbf{H}^{(0)})) + \mathbf{H}^{(0)})$$

### Why Is This Critical?

The CNN block computes **motion features** (velocity,
acceleration). These are useful but they are not the only
useful information. The original projected features from
Stage 1 encode **positional information** — where the hand
is at each frame.

Without the residual connection:
```text
Output = motion features only
→ model knows HOW the hand moves but not WHERE it is
```

With the residual connection:
```text
Output = motion features + positional features
→ model knows BOTH where the hand is AND how it is moving
```

For sign recognition, both are essential:
- "THINK": finger touches **temple** (position) with a **tapping** motion (velocity)
- "FEEL": finger touches **chest** (position) with a **circular** motion (velocity)

Remove position → cannot distinguish temple from chest
Remove velocity → cannot distinguish tap from circle

The residual connection ensures both signals survive.

### The Gradient Flow Argument

During backpropagation, the gradient must flow backward through
the CNN layers. If the CNN learns to suppress some features
(output near zero), those features get zero gradient — the
projection weights before them stop learning.

The residual connection creates a **gradient highway**:

$$\frac{\partial \mathcal{L}}{\partial \mathbf{H}^{(0)}} =
\frac{\partial \mathcal{L}}{\partial \mathbf{H}^{(1)}} \cdot
\underbrace{\left(1 + \frac{\partial \text{CNN}(\mathbf{H}^{(0)})}{\partial \mathbf{H}^{(0)}}\right)}_{\text{never zero due to the +1}}$$

The $+1$ term means the gradient can always flow directly
backward through the residual connection, even if the CNN
path is suppressed. The projection weights always receive
some gradient signal.

## 9. Padding = 1 — Why the Sequence Length Does Not Change

Your conv layers use `padding=1`. This adds one zero on each
side of the time axis before convolution:

```text
Original: [f₁, f₂, f₃, ..., f₆₄]         length = 64

Padded:   [0, f₁, f₂, f₃, ..., f₆₄, 0]   length = 66

After conv (kernel=3): length = 66 - 3 + 1 = 64
```

Without padding, a kernel of size 3 would reduce the sequence:
$64 - 3 + 1 = 62$ frames. Two layers would give $60$ frames.
The residual connection would then fail because you cannot add
a $(64, 64, 256)$ tensor to a $(64, 60, 256)$ tensor.

`padding=1` preserves the $T=64$ dimension so that:
1. The residual addition works dimensionally
2. The positional encoding at Stage 3 works on the same $T$
3. The Transformer at Stage 4 receives a consistent $T=64$

The padding zeros at the boundaries are a minor artefact —
the kernel at $t=1$ sees one zero and two real frames. At $t=64$
it sees two real frames and one zero. This boundary effect is
negligible in practice.

## 10. The Full Shape Flow Through the CNN Block

```text
Input to CNN block:
  H⁰ shape: (B=64, T=64, C=256)

Transpose (PyTorch Conv1d requires B, C, T):
  (64, 64, 256) → (64, 256, 64)

Conv1d layer 1 (kernel=3, padding=1):
  Input:  (64, 256, 64)   ← 256 input channels, 64 time steps
  Kernel: (256, 256, 3)   ← 256 output channels, 256 input channels, size 3
  Output: (64, 256, 64)   ← same shape (padding preserves T)

GELU activation:
  (64, 256, 64) → (64, 256, 64)  ← same shape, values changed

Dropout:
  (64, 256, 64) → (64, 256, 64)  ← same shape, 30% zeroed

Conv1d layer 2 (kernel=3, padding=1):
  Input:  (64, 256, 64)
  Output: (64, 256, 64)

GELU + Dropout:
  (64, 256, 64) → (64, 256, 64)

Transpose back:
  (64, 256, 64) → (64, 64, 256)

Residual addition + LayerNorm:
  (64, 64, 256) + (64, 64, 256) = (64, 64, 256)

Output H¹: (B=64, T=64, C=256)  ← same shape as input
```

The entire CNN block is **shape-preserving**: $(B, T, 256)$
in, $(B, T, 256)$ out. Only the values change.

## 11. Parameter Count of the CNN Block

Each Conv1d(256, 256, kernel_size=3):

$$\text{parameters} = d_{\text{out}} \times d_{\text{in}} \times k + d_{\text{out}}$$
$$= 256 \times 256 \times 3 + 256 = 196{,}608 + 256 = 196{,}864$$

Two Conv1d layers plus LayerNorm:

$$2 \times 196{,}864 + 2 \times 256 = 394{,}240 \text{ parameters}$$

This matches the parameter count table in your report. These
394,240 parameters collectively learn to detect all the local
temporal patterns (velocity, acceleration, holds, peaks)
that are useful for distinguishing between your 250 ASL signs.

## 12. Why Not Just Use the Transformer for Everything?

A fair question. The Transformer already handles frame
relationships via self-attention. Why add a CNN?

| | 1D-CNN | Transformer Self-Attention |
|---|---|---|
| Scope | Local (3-5 adjacent frames) | Global (all 64 frames) |
| Computation | $O(T \times k)$ per layer | $O(T^2)$ per layer |
| What it learns | Velocity, acceleration, holds | Which frames to compare |
| Inductive bias | Temporal locality matters | All relationships equal |
| Position-aware | Yes (sliding window is local) | Needs explicit PE |

The CNN provides **local inductive bias** — it builds in the
assumption that adjacent frames are more related than distant
frames. This is physically true for sign language: the hand at
frame $t$ is always most similar to the hand at frames $t-1$
and $t+1$.

By giving the Transformer pre-computed local motion features
(instead of raw projected coordinates), you let the Transformer
focus on what it is best at: deciding which parts of the sign
are most informative and how they relate across the full
temporal extent.

The combination is greater than either alone:

```text
CNN:         "the hand is accelerating upward between frames 20-25"
Transformer: "this acceleration at frames 20-25 is the most
              important part of this sign — attend to it"
Classifier:  "this pattern of acceleration = AIRPLANE"
```

## 14. The Formula to Remember

For one output channel $k$ at time $t$:

$$\boxed{
\text{out}_k(t) = \sum_{c=1}^{256}
\sum_{i \in \{-1,0,+1\}} w_{k,c,i} \cdot h_c(t+i) + b_k
}$$

- Outer sum: over all 256 input channels
- Inner sum: over the 3 kernel positions ($t-1$, $t$, $t+1$)
- $w_{k,c,i}$: weight for output channel $k$, input channel $c$, offset $i$
- $h_c(t+i)$: value of input channel $c$ at frame $t+i$

This operation, repeated for all 256 output channels at all
64 time positions, is what transforms raw projected features
into rich local motion representations ready for the Transformer.
