
> **One sentence summary:** Positional encoding adds a unique
> mathematical fingerprint to each frame's representation so that
> the Transformer — which otherwise treats all frames as an
> unordered set — knows that frame 5 comes before frame 6 and
> after frame 4.

## 1. Your Intuition About Tokens — Partially Right

You asked if positional encoding is like tokenization in NLP.
Let us clarify the relationship precisely.

### In Natural Language Processing (NLP)

```
Sentence: "The cat sat on the mat"

Step 1 — Tokenization: convert words to integer IDs
  "The" → 2045
  "cat" → 8303
  "sat" → 6341
  "on"  → 319
  "the" → 2045
  "mat" → 12493

Step 2 — Embedding: convert IDs to vectors
  2045 → [0.2, -0.5, 0.8, ..., 0.3]  (512 numbers)
  8303 → [0.7,  0.1, -0.3, ..., 0.9]

Step 3 — Positional Encoding: add position information
  Position 1 → add [sin(1/1), cos(1/1), sin(1/100), ...]
  Position 2 → add [sin(2/1), cos(2/1), sin(2/100), ...]
```

Tokenization converts words into numbers.
Embedding converts those numbers into rich vectors.
Positional encoding tells the model WHERE each token sits.

### In Your ASL Model

You skip the first two steps because you already have vectors.
Your 345 landmark coordinates are already a rich representation
of each frame — you do not need tokenization or embedding lookup.

```
Frame 20: [x_lm0, y_lm0, z_lm0, ..., z_lm114]  ← already a vector
              ↓ Linear Projection
          [f₁, f₂, ..., f₂₅₆]                   ← 256-dim vector

Then directly:
              ↓ Positional Encoding
          [f₁ + PE₁(20), f₂ + PE₂(20), ..., f₂₅₆ + PE₂₅₆(20)]
```

So positional encoding in your model is **step 3 only** — you do
not need steps 1 and 2 because landmark vectors are already
semantically rich.

The analogy to tokenization: tokens give words an identity.
Positional encoding gives positions an identity. You already
have frame identities (the landmark vectors). You just need
position identities.

## 2. The Core Problem — Why the Transformer Is Blind to Order

Before understanding the solution, you must deeply understand
the problem.

### The Transformer Sees a Set, Not a Sequence

Self-attention computes:

$$\text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) =
\text{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}}\right)\mathbf{V}$$

Look at this formula carefully. The matrices $\mathbf{Q}$,
$\mathbf{K}$, $\mathbf{V}$ are computed from the input sequence.
But the formula itself involves no notion of order. It computes
dot products between every pair of frames — but a dot product
between frame 5 and frame 20 gives the same number regardless
of whether they are 15 positions apart or adjacent.

The Transformer, as originally designed, is **permutation
invariant**: if you shuffle the 64 frames into a random order,
the output is also shuffled in the exact same way — the model
cannot detect that anything changed.

### Proof by Permutation

Take your 64 frames and shuffle them:

```
Original:  [frame_1,  frame_2,  frame_3,  ..., frame_64]
Shuffled:  [frame_42, frame_7,  frame_19, ..., frame_3 ]
```

Feed both to a Transformer without positional encoding.
The attention scores between frame_42 and frame_7 are
**identical** in both cases — the model does not know
that in the original, frames 1 and 2 were adjacent.

For image classification, this does not matter much (a dog
is a dog regardless of pixel order in some sense). For
sign language recognition, this is catastrophic:

```
"DRINK": hand moves TO mouth (upward trajectory)
"GIVE":  hand moves AWAY from body (outward trajectory)

Without position: the model sees 64 frames of hand movement
                  but cannot tell which came first
→ DRINK and GIVE look identical (same frames, different order)
→ model cannot distinguish them
```

## 3. The Solution Space — Three Approaches

When researchers discovered this problem, they considered
three solutions:

### Option A: Learned Position Embeddings

Create a trainable embedding table:

$$\mathbf{E}_{\text{pos}} \in \mathbb{R}^{T_{\text{max}} \times d_{\text{model}}}$$

Position 1 gets a learned vector. Position 2 gets a different
learned vector. These vectors are updated by backpropagation
just like any other weight.

**Problem:** If you train on sequences up to length 64 and then
try to run the model on a sequence of length 80, there is no
embedding for positions 65-80. The model cannot extrapolate
beyond its training length.

### Option B: One-Hot Position Encoding

Assign each position a one-hot vector:

$$\text{pos}_1 = [1, 0, 0, ..., 0]$$
$$\text{pos}_2 = [0, 1, 0, ..., 0]$$
$$\text{pos}_{64} = [0, 0, 0, ..., 1]$$

**Problem:** These vectors are all orthogonal. The model
learns that position 1 ≠ position 2, but it cannot learn
that positions 1 and 2 are **close** while positions 1 and
64 are **far**. Relative distance between positions is
invisible.

### Option C: Sinusoidal Positional Encoding (What You Use)

Use mathematical functions — specifically sine and cosine —
to generate position vectors. These are **not learned**.
They are fixed mathematical formulas that produce unique,
structured patterns for each position.

This is what Vaswani et al. chose in the original Transformer
paper, and what your model uses.

## 4. Why Sine and Cosine — The Deep Reason

This is the part nobody explains well. Why sine and cosine
specifically? Why not squares, or cubes, or random patterns?

### The Binary Analogy — Building Intuition

Consider how integers are represented in binary:

```
Position  1: 0 0 0 0 0 1
Position  2: 0 0 0 0 1 0
Position  3: 0 0 0 0 1 1
Position  4: 0 0 0 1 0 0
Position  8: 0 0 1 0 0 0
Position 16: 0 1 0 0 0 0
Position 32: 1 0 0 0 0 0
```

Notice the pattern:
- The rightmost bit alternates every 1 position
- The next bit alternates every 2 positions
- The next every 4 positions
- The next every 8 positions
- And so on (powers of 2)

Each bit oscillates at a different frequency. The combination
of all bits gives a unique, structured representation of every
integer.

**Sinusoidal positional encoding is the continuous version
of binary counting.**

Instead of bits that flip between 0 and 1, you use sine and
cosine waves that oscillate smoothly between -1 and +1.
Instead of doubling the period (1, 2, 4, 8...), you use
exponentially increasing periods.

```
Dimension 0:   sine wave, period = 2π (fastest)
Dimension 1:   cosine wave, period = 2π
Dimension 2:   sine wave, period = 2π × 100^(2/256)
Dimension 3:   cosine wave, same period
...
Dimension 254: sine wave, period = 2π × 10000 (slowest)
Dimension 255: cosine wave, period = 2π × 10000
```

Each pair of dimensions oscillates at a different frequency.
The combination of all 256 values gives a unique fingerprint
for every position.

## 5. The Formula — Every Symbol Explained

$$\text{PE}(t, 2i) = \sin\!\left(\frac{t}{10000^{2i/d}}\right)$$

$$\text{PE}(t, 2i+1) = \cos\!\left(\frac{t}{10000^{2i/d}}\right)$$

Where:
- $t \in \{0, 1, 2, \ldots, 63\}$ — **frame index** (which frame)
- $i \in \{0, 1, 2, \ldots, 127\}$ — **dimension pair index**
- $d = d_{\text{model}} = 256$ — total model dimension
- $2i$ — even dimensions get sine
- $2i+1$ — odd dimensions get cosine

### Breaking Down the Frequency Term

$$\frac{1}{10000^{2i/d}}$$

This is the **angular frequency** — how fast the wave oscillates.

- When $i = 0$: frequency $= \frac{1}{10000^0} = 1.0$ (fastest)
- When $i = 64$: frequency $= \frac{1}{10000^{0.5}} = \frac{1}{100} = 0.01$
- When $i = 127$: frequency $= \frac{1}{10000^{0.992}} \approx \frac{1}{9752}$ (slowest)

The frequencies decrease exponentially from 1.0 to 1/10000
across the 128 dimension pairs. This is the continuous analogue
of the binary pattern where periods go 1, 2, 4, 8, 16...
 
### What Each Dimension Encodes

```
Dimensions 0-1 (fastest sine/cosine, period ≈ 6.28):
  These oscillate so fast that adjacent frames have
  very different values. They encode FINE-GRAINED
  position — distinguishing consecutive frames.

Dimensions 254-255 (slowest, period ≈ 62,832):
  These oscillate so slowly that across 64 frames
  the value barely changes. They encode COARSE position —
  distinguishing the first half from the second half.
```

Together, the 256 dimensions create a multi-resolution
representation of position — like a clock with many hands
running at different speeds.

## 6. A Concrete Worked Example

Let us compute $\text{PE}$ for three frames and two dimensions
(simplified to $d=4$ for readability):

$$\text{PE}(t, 0) = \sin\!\left(\frac{t}{10000^{0}}\right) = \sin(t)$$

$$\text{PE}(t, 1) = \cos\!\left(\frac{t}{10000^{0}}\right) = \cos(t)$$

$$\text{PE}(t, 2) = \sin\!\left(\frac{t}{10000^{0.5}}\right) = \sin\!\left(\frac{t}{100}\right)$$

$$\text{PE}(t, 3) = \cos\!\left(\frac{t}{10000^{0.5}}\right) = \cos\!\left(\frac{t}{100}\right)$$

Computing for frames $t = 0, 1, 2$:

| Frame $t$ | $\sin(t)$ | $\cos(t)$ | $\sin(t/100)$ | $\cos(t/100)$ |
|---|---|---|---|---|
| 0 | 0.000 | 1.000 | 0.000 | 1.000 |
| 1 | 0.841 | 0.540 | 0.010 | 1.000 |
| 2 | 0.909 | -0.416 | 0.020 | 1.000 |

Each frame gets a unique 4-dimensional fingerprint.
Frame 0: $[0.000, 1.000, 0.000, 1.000]$
Frame 1: $[0.841, 0.540, 0.010, 1.000]$
Frame 2: $[0.909, -0.416, 0.020, 1.000]$

No two frames have the same fingerprint.

## 7. The Key Properties — Why This Design Is Genius

### Property 1: Every Position Is Unique

No two values of $t$ produce the same PE vector. This is
guaranteed by the mathematics of sine and cosine — at any
given frequency, no two integer positions within a reasonable
range map to the same value.

### Property 2: Relative Distance Is Encoded

This is the most important property. For any fixed offset $k$:

$$\text{PE}(t + k) \text{ can be expressed as a linear function of } \text{PE}(t)$$

Specifically, using the trigonometric addition formulas:

$$\sin(t + k) = \sin(t)\cos(k) + \cos(t)\sin(k)$$
$$\cos(t + k) = \cos(t)\cos(k) - \sin(t)\sin(k)$$

This means: **knowing the PE at position $t$ and the offset $k$,
you can compute the PE at position $t+k$ using a linear
transformation** (a rotation matrix in 2D).

The Transformer can therefore learn to attend to frames that
are "exactly $k$ positions after frame $t$" by learning the
appropriate linear transformation on the PE vectors. Relative
distances are not just representable — they are computable.

For your ASL model: "attend to the frame 5 positions later"
is a learnable operation. The model can discover that the end
of a hand movement (frame $t+5$) is relevant to understanding
the start of the movement (frame $t$).

### Property 3: Bounded Values

All PE values lie in $[-1, +1]$. They never explode to large
magnitudes regardless of position. When added to the projected
frame vectors $\mathbf{H}^{(0)}$, they do not dominate the
representation.

### Property 4: Generalization Beyond Training Length

If your model trained on $T=64$ frames, it can still process
a sequence of 80 frames — just compute $\text{PE}(65)$,
$\text{PE}(66)$... using the same formula. No new weights
needed. This is why sinusoidal PE generalises while learned
embeddings cannot.

## 8. How It Is Added — The Operation

The positional encoding is added **element-wise** to the
projected frame vectors:

$$\mathbf{H}^{(2)} = \mathbf{H}^{(1)} + \mathbf{PE}$$

Where:
- $\mathbf{H}^{(1)} \in \mathbb{R}^{64 \times 256}$ — output of CNN block
- $\mathbf{PE} \in \mathbb{R}^{64 \times 256}$ — positional encoding matrix
- $\mathbf{H}^{(2)} \in \mathbb{R}^{64 \times 256}$ — PE-enriched representation

The addition is the simplest possible operation. No weights.
No parameters. Just $+$.

After addition, each frame's 256-dimensional vector contains:
- The sign content (from the projected landmarks + CNN)
- The temporal position fingerprint (from PE)

The Transformer can now ask: "how does the content of frame 5
relate to the content of frame 20, given that frame 5 is at
the beginning of the sign and frame 20 is in the middle?"

## 9. Precomputed and Registered as a Buffer

In your code:

```python
class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=128, dropout=0.1):
        super().__init__()
        self.dropout = nn.Dropout(p=dropout)

        # Pre-compute the entire PE matrix ONCE
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len).unsqueeze(1).float()
        div_term = torch.exp(
            torch.arange(0, d_model, 2).float() *
            (-math.log(10000.0) / d_model)
        )
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        pe = pe.unsqueeze(0)   # (1, max_len, d_model)

        # Register as BUFFER not as parameter
        self.register_buffer('pe', pe)

    def forward(self, x):
        # x: (B, T, d_model)
        # self.pe: (1, max_len, d_model) → slice to (1, T, d_model)
        x = x + self.pe[:, :x.size(1)]
        return self.dropout(x)
```

### Why `register_buffer` and Not `nn.Parameter`?

```
nn.Parameter:  tracked by optimizer, updated by backpropagation
register_buffer: NOT tracked by optimizer, never updated

PE is mathematical constants. They should never change.
If backpropagation updated them, they would stop being
sinusoidal and lose all their mathematical properties.
```

`register_buffer` means:
- PE moves to GPU with `.to(device)` automatically
- PE is saved in the checkpoint with `torch.save`
- PE is NOT updated by the optimizer
- PE is invisible to `model.parameters()`

### Why Pre-compute?

The PE matrix is computed once in `__init__` and stored.
During each forward pass, we just look up pre-computed values
and slice to the right length:

```python
self.pe[:, :x.size(1)]   # slice first T positions
```

Computing sine and cosine every forward pass would waste
time. Pre-computing is a standard optimization.

## 10. Dropout After PE — Why?

```python
return self.dropout(x)   # dropout rate = 0.1
```

After adding the positional encoding, a small dropout is
applied. This prevents the model from relying too heavily
on exact positional information.

For sign language this makes sense: the sign "DRINK" should
be recognised whether it starts at frame 5 or frame 20 in
the sliding window. By randomly dropping some positional
information during training, the model learns to classify
signs based on their content AND their general temporal
structure — not their exact position in the window.

## 11. Positional Encoding vs Tokenization — Final Clarification

| | NLP Tokenization | NLP Positional Encoding | Your ASL PE |
|---|---|---|---|
| **Input** | Raw text | Token embedding vectors | Frame landmark vectors |
| **What it creates** | Integer IDs for words | Position fingerprints | Position fingerprints |
| **Learned?** | Yes (embedding table) | Sometimes / No (sinusoidal) | No (sinusoidal) |
| **Added to what?** | Nothing (it IS the representation) | The token embeddings | The projected frame vectors |
| **Purpose** | Give words an identity | Give positions an identity | Give frames a position identity |

Your PE is equivalent to NLP positional encoding only.
You skip tokenization entirely because landmark vectors are
already semantically rich representations.

## 12. Connection to Your ASL Project — What PE Enables

Without PE, your Transformer would compute the same output
for these two inputs:

```
Sign A: frame sequence [open_hand, moving_up, closed_fist]
Sign B: frame sequence [closed_fist, moving_up, open_hand]

Without PE: both produce identical Transformer output
            (same frames, different order)
→ model cannot distinguish them

With PE:
  Sign A: open_hand+PE(0), moving_up+PE(1), closed_fist+PE(2)
  Sign B: closed_fist+PE(0), moving_up+PE(1), open_hand+PE(2)
→ completely different inputs to the Transformer
→ model correctly learns these are different signs
```

For a real ASL pair: DRINK (hand moves TO mouth) vs GIVE
(hand moves AWAY from body) — the frames are similar but
the temporal order is reversed. PE makes these distinguishable.

| **What PE does** | Adds a unique temporal fingerprint to each frame |

## 14. The Formula to Remember

$$\boxed{
\text{PE}(t, 2i) = \sin\!\left(\frac{t}{10000^{2i/d}}\right),
\quad
\text{PE}(t, 2i+1) = \cos\!\left(\frac{t}{10000^{2i/d}}\right)
}$$

- $t$ = frame index (0 to 63 in your model)
- $i$ = dimension pair index (0 to 127)
- $d$ = model dimension (256)
- Even dimensions → sine (fast oscillations at small $i$)
- Odd dimensions → cosine (same frequency as adjacent sine)
- As $i$ increases → frequency decreases → slower oscillation

The combination of 128 sine/cosine pairs at exponentially
decreasing frequencies creates a unique, structured fingerprint
for every frame position — the continuous analogue of binary
counting.
