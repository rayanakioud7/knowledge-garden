

---

> **One sentence summary:** Global Average Pooling collapses the entire 64-frame sequence into a single 256-dimensional vector by averaging across time — but only over real frames, not padding — giving the classifier one compact summary of the entire sign.

---

## 1. Where We Are

After passing through all Transformer encoder layers, you have:

```text
Output of final Transformer layer:  Z^(L)  shape: (64, 256)
```

Where $L$ is the number of layers (4 in base config, 6 in scaled config).

Each of the 64 rows is a 256-dimensional vector representing one frame, enriched by:
- Local motion patterns from the 1D-CNN
- Global temporal context from multi-head attention (repeated $L$ times)
- Deep non-linear processing from the feed-forward blocks (repeated $L$ times)

The problem: your classifier needs **one fixed-size vector** to make a prediction. It cannot accept a sequence of 64 vectors — it needs a single summary.

Global Average Pooling (GAP) collapses the $(64, 256)$ tensor into a single $(256,)$ vector.

---

## 2. The Naive Approach — And Why It Fails

The simplest collapse is to just average all 64 frames:

$$\mathbf{z}_{\text{naive}} = \frac{1}{64} \sum_{t=1}^{64} \mathbf{h}^{(L)}_t$$

This seems reasonable. But there is a critical flaw.

Your sequences are center-padded with zeros. A sign of median length 21 frames inside a 64-frame window looks like this:

```text
Frame layout:
[0,0,...,0 | sign frame 1, 2, ..., 21 | 0,0,...,0]
 ←21 zeros→  ←────── real sign ──────→  ←22 zeros→
```

If you average over all 64 frames:

$$\mathbf{z}_{\text{naive}} = \frac{1}{64} \left( 21 \times \mathbf{h}_{\text{real}} + 43 \times \mathbf{0} \right) = \frac{21}{64} \mathbf{h}_{\text{real}}$$

The padding zeros dilute the signal by a factor of $\frac{21}{64} \approx 0.33$.

The classifier receives a vector that is roughly **one third** the magnitude it should be. For a short sign, the model effectively reads mostly silence.

This was **Bug Fix 3** identified in Experiment 4. The fix is to average only over real frames.

---

## 3. Masked Global Average Pooling — The Correct Version

The production implementation computes the average exclusively over non-padding frames.

### Step 1: Identify real frames

A frame is real if at least one of its 690 feature values is non-zero after standardisation:

$$m_t = \begin{cases} 1 & \text{if } \|\mathbf{x}_t\|_\infty > 0 \quad \text{(real frame)} \\ 0 & \text{if } \mathbf{x}_t = \mathbf{0} \quad \text{(padding)} \end{cases}$$

In practice, the padding mask is computed before the Transformer as:

```python
padding_mask = (x == 0.0).all(dim=2)   # True = padding
real_mask    = ~padding_mask            # True = real
```

Shape of `real_mask`: $(B, 64)$ — one boolean per frame per sample.

### Step 2: Count real frames per sample

$$n_{\text{real}} = \sum_{t=1}^{64} m_t \quad \in \{1, 2, \ldots, 64\}$$

Clipped to a minimum of 1 to avoid division by zero:

$$n_{\text{real}} = \max\!\left(\sum_{t=1}^{64} m_t,\ 1\right)$$

### Step 3: Compute the masked average

$$\mathbf{z} = \frac{\displaystyle\sum_{t=1}^{64} m_t \cdot \mathbf{h}^{(L)}_t}{n_{\text{real}}} \in \mathbb{R}^{256}$$

In matrix form:

$$\mathbf{z} = \frac{\mathbf{m}^\top \mathbf{H}^{(L)}}{n_{\text{real}}}$$

Where $\mathbf{m} \in \{0,1\}^{64}$ and $\mathbf{H}^{(L)} \in \mathbb{R}^{64 \times 256}$.

## 4. A Concrete Worked Example

**Sign:** DRINK, 21 real frames, center-padded to 64.

```text
Real frame mask:
m = [0,0,...,0, 1,1,...,1, 0,0,...,0]
    ←21 zeros→  ←21 ones→  ←22 zeros→

n_real = 21
```

**Frame representations after final Transformer layer:**

```text
h₁  = [0, 0, ..., 0]         ← padding (zeros)
h₂  = [0, 0, ..., 0]         ← padding
...
h₂₂ = [0.42, -0.18, ..., 0.71]   ← first real frame (preparation)
h₂₃ = [0.38, -0.22, ..., 0.69]   ← second real frame
...
h₄₂ = [0.91, 0.03, ..., -0.44]   ← last real frame (retraction)
h₄₃ = [0, 0, ..., 0]         ← padding
...
h₆₄ = [0, 0, ..., 0]         ← padding
```

**Masked average:**

$$\mathbf{z} = \frac{1}{21} \sum_{t=22}^{42} \mathbf{h}^{(L)}_t$$

The padding frames contribute exactly zero to the sum (because $m_t = 0$ for them). The result is a faithful average of the 21 real sign frames only.

**Comparison with naive average:**

| Method | Sign magnitude | What the classifier sees |
|--------|---------------|--------------------------|
| Naive (all 64 frames) | $\times \frac{21}{64} = \times 0.328$ | Diluted signal |
| Masked (21 real frames) | $\times 1.0$ | Full signal |

The masked version gives the classifier the correct-magnitude summary regardless of sign length.

---

## 5. Why Average Instead of Other Pooling Methods?

Several alternatives exist. Here is why average pooling was chosen:

### Alternative 1: Take the last real frame

$$\mathbf{z} = \mathbf{h}^{(L)}_{t_{\text{last real}}}$$

**Problem:** The last real frame is the retraction phase (hand returning to rest). This is the least informative moment of the sign. The preparation and core motion would be ignored.

### Alternative 2: Take the first real frame

**Problem:** The first frame is the preparation phase. Same issue — the most informative core sign motion is in the middle.

### Alternative 3: Max pooling

$$z_d = \max_{t: m_t=1} h^{(L)}_{t,d} \quad \text{for each dimension } d$$

**Problem:** Takes the maximum value in each dimension independently. The maximum of dimension 42 might come from frame 15, while the maximum of dimension 87 comes from frame 31. The resulting vector is a chimera that never actually existed at any single point in time.

### Why average pooling wins

Average pooling gives **equal weight to every real frame**. A sign is a process — the beginning, middle, and end all carry information. The model has already used attention to weight frames internally during the Transformer layers. GAP then takes an unweighted summary of those enriched representations.

The sign classification is a property of the entire sequence, not of any single moment. Average pooling respects this.

---

## 6. The Effect of the Attention Layers on GAP

Here is a subtle but important point.

Before the Transformer layers, the frame representations only contain local information. Global average pooling over those would just average 64 independent frames — not very informative.

After the Transformer layers, each frame representation has been enriched with information from all other frames via self-attention.

Frame 20 (core mouth motion for DRINK) now contains:
- Its own local features
- Information borrowed from frame 5 (preparation phase)
- Information borrowed from frame 40 (retraction phase)
- Context from frame 30 (mid-motion)

So when GAP averages over all real frames, it is averaging over 21 **richly contextualised** representations, each of which already "knows" about the entire sign.

This is why GAP after a Transformer is much more powerful than GAP after a plain CNN — the Transformer has pre-aggregated the temporal information within each frame's representation.

## 7. Shape Transformations

```text
Output of final Transformer layer:
  H^(L)      (B, 64, 256)

Real frame mask (computed before Transformer, reused here):
  real_mask  (B, 64)       ← boolean, True = real frame

Zero out padding frames:
  H^(L) * real_mask[:, :, None]   (B, 64, 256)

Sum over time dimension:
  sum = (H^(L) * mask).sum(dim=1)   (B, 256)

Count real frames:
  counts = real_mask.sum(dim=1).clamp(min=1)   (B,)

Divide:
  z = sum / counts[:, None]   (B, 256)

Output:
  z   (B, 256)   ← one summary vector per sign in the batch
```

The temporal dimension (64) is gone. The batch dimension ($B$) and feature dimension (256) remain.

## 8. The Code in Your Model

In `src/model.py`, inside `ASLTransformerV5.forward()`:

```python
# Stage 5: Masked Global Average Pooling

real_mask   = ~padding_mask                    # (B, T) — True = real
real_counts = real_mask.sum(1, keepdim=True)   # (B, 1) — how many real frames
             .float().clamp(min=1.0)           # avoid division by zero

x = (x * real_mask.unsqueeze(2).float()        # zero out padding frames
    ).sum(1) / real_counts                     # sum then divide

# x: (B, 256)  ← ready for classifier
```

Line by line:

| Line | Operation | Shape |
|------|-----------|-------|
| `real_mask = ~padding_mask` | Invert: True = real | $(B, 64)$ |
| `real_counts = real_mask.sum(1, keepdim=True)` | Count real frames | $(B, 1)$ |
| `.float().clamp(min=1.0)` | Ensure no division by zero | $(B, 1)$ |
| `x * real_mask.unsqueeze(2).float()` | Zero out padding rows | $(B, 64, 256)$ |
| `.sum(1)` | Sum over time | $(B, 256)$ |
| `/ real_counts` | Divide by real frame count | $(B, 256)$ |

## 9. What the Pooled Vector Represents

After masked GAP, $\mathbf{z} \in \mathbb{R}^{256}$ is the model's best single-vector summary of the entire sign.

Intuitively it captures:
- The average hand position across the sign trajectory
- The average velocity profile of the sign
- The average facial expression throughout
- The dominant motion pattern

But because each frame was enriched by attention before pooling, $\mathbf{z}$ also implicitly captures:
- The relationship between the start and end of the sign
- The co-occurrence of hand position and facial expression
- The temporal rhythm of the sign

This vector then goes directly into the classification head.

## 10. Bug Fix 3 Revisited — The Quantitative Impact

Experiment 3 (v3) suffered from unmasked global average pooling.

For a median-length sign of 21 frames padded to 64:

$$\text{Dilution factor (naive)} = \frac{21}{64} \approx 0.328$$

The classification vector had magnitude about one-third of what it should be.

After fixing this in Experiment 4 (v4):

| Metric | v3 (unmasked) | v4 (masked) | Gain |
|--------|---------------|-------------|------|

## 11. Masked GAP vs Attention Masking — Two Different Things

Both appear in your model and both use the same padding mask. They are different operations:

| | Attention masking | Masked GAP |
|---|---|---|
| **Where** | Inside each Transformer layer | After all Transformer layers |
| **What it does** | Prevents frames from attending to padding | Prevents padding from contributing to the summary vector |
| **Effect** | Real frames do not receive information from padding | Padding frames do not dilute the final pooled representation |
| **Without it** | Real frames get "noise" from attending to zeros | Short signs get magnitude-diluted classification vectors |

Both are necessary. Removing either one degrades performance.

## 12. Summary

| Concept | Definition |
|---------|------------|
| **Global Average Pooling** | Collapse time dimension by averaging |
| **Masked** | Only average over real (non-padding) frames |
| **Input** | $(B, 64, 256)$ — 64 enriched frame representations |
| **Output** | $(B, 256)$ — one summary vector per sign |
| **Real frame mask** | Boolean $(B, 64)$ — True = real, False = padding |
| **Why not naive average** | Padding zeros dilute the signal by up to 67% for short signs |
| **Why not max pooling** | Mixes dimensions from different time steps incoherently |
| **Why not last frame** | Retraction phase is least informative |
| **Why average works** | Attention has already enriched each frame with global context — averaging is a faithful summary |

## 13. The Full Equation — Every Symbol Explained

$$\boxed{\mathbf{z} = \frac{\displaystyle\sum_{t=1}^{T} m_t \cdot \mathbf{h}^{(L)}_t}{\displaystyle\max\!\left(\sum_{t=1}^{T} m_t,\ 1\right)}}$$

| Symbol | Shape | Meaning |
|--------|-------|---------|
| $T = 64$ | scalar | Fixed sequence length |
| $\mathbf{h}^{(L)}_t$ | $(256,)$ | Frame $t$ after final Transformer layer |
| $m_t \in \{0,1\}$ | scalar | 1 if frame $t$ is real, 0 if padding |
| $\sum m_t$ | scalar | Number of real frames in this sign |
| $\max(\cdot, 1)$ | scalar | Prevents division by zero for all-padding edge case |
| $\mathbf{z}$ | $(256,)$ | Final summary vector — input to classifier |

---

## 14. What Comes Next

$\mathbf{z} \in \mathbb{R}^{256}$ (base) or $\mathbb{R}^{512}$ (scaled) is now passed to the classification head.

The classification head is a two-layer MLP:

$$\hat{\mathbf{y}} = \mathbf{W}_2 \cdot \text{GELU}(\mathbf{W}_1 \mathbf{z} + \mathbf{b}_1) + \mathbf{b}_2 \in \mathbb{R}^{250}$$

This produces 250 raw scores — one per ASL sign class. The highest score is the model's prediction.

That is concept 15: **CrossEntropyLoss** — what the model is actually optimising, and how those 250 scores are turned into a probability distribution and compared to the true label.
