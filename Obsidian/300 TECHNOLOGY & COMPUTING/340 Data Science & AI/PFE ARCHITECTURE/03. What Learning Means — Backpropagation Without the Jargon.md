> **One sentence summary:** The model makes a prediction, measures
> how wrong it was, and then traces that error backward through
> every weight in the network — adjusting each one by exactly the
> amount needed to be slightly less wrong next time.

---

## 1. The Setup — What We Have

At this point in the story we have:

- A network with millions of weights (e.g. $\mathbf{W}_{\text{proj}}$
  has 88,320 weights — all initialised randomly)
- A training set of 74,841 sign sequences
- A loss function that measures how wrong the prediction is
- A goal: adjust all the weights until predictions are correct

The question is: **how do you adjust 3,772,922 weights
simultaneously and efficiently?**

The answer is backpropagation.

---

## 2. The Intuition — A Student Correcting Their Mistakes

Imagine a student who guesses the answer to a maths problem:

```text
Problem:  What is 3 × 7?
Student:  I think it is 24.
Correct:  It is 21.
Error:    24 - 21 = 3  (too high by 3)
```

The student does not randomly guess again. They trace back
through their reasoning:

```python
"I computed 3 × 8 = 24 instead of 3 × 7"
→ I over-counted by one group of 3
→ I should subtract 3 from my answer next time
→ Specifically: when I see ×7, I should not add that extra 3
```

They identified **which step caused the error** and **by how much**
they need to correct it. Next time they see $3 \times 7$, they
will get 21.

**Backpropagation is this process** — tracing the error backward
through every computation to find how much each weight contributed
to the mistake.

---

## 3. The Forward Pass — Making a Prediction

Before we can correct anything, the model must make a prediction.
This is called the **forward pass** — data flows forward through
the network from input to output.

For one training sample (one sign sequence):

```text
Input X  (64, 345)   ← one sign video as landmarks
    ↓
Linear Projection    ← X × W_proj + b  →  H⁰ (64, 256)
    ↓
1D-CNN               ← local motion features
    ↓
Positional Encoding  ← temporal order injected
    ↓
Transformer          ← global context
    ↓
Global Avg Pool      ← (64, 256) → (256,)
    ↓
Classifier           ← (256,) → (250,) logits
    ↓
Softmax              ← (250,) probabilities
    ↓
Prediction: "blow" with probability 0.003  ← WRONG (true label is "blow")
```

Wait — the model predicted "blow" but with only 0.003 probability.
The true label is "blow" and it should be close to 1.0. Something
is very wrong at the start of training (random weights produce
random predictions).

---

## 4. The Loss — Measuring How Wrong

The loss function takes the prediction and the true label and
produces one number: **how wrong was the prediction?**

For cross-entropy loss with true label "blow" (class index 25):

$$\mathcal{L} = -\log(\hat{y}_{25})$$

Where $\hat{y}_{25}$ is the predicted probability for class 25.

```text
If prediction for "blow" = 0.003:
    L = -log(0.003) = 5.81   ← very high loss (very wrong)

If prediction for "blow" = 0.8:
    L = -log(0.8)  = 0.22   ← low loss (nearly right)

If prediction for "blow" = 1.0:
    L = -log(1.0)  = 0.0    ← perfect prediction
```

The loss $\mathcal{L}$ is a single number. The entire goal of
training is to make this number as small as possible across all
74,841 training samples.

---

## 5. The Gradient — Which Direction to Move Each Weight

The loss $\mathcal{L}$ depends on every weight in the network.
If we change one weight slightly, the loss changes slightly.

The **gradient** of the loss with respect to a weight $w$ tells
us two things:

1. **Direction:** Should we increase or decrease $w$ to reduce $\mathcal{L}$?
2. **Magnitude:** How sensitive is $\mathcal{L}$ to changes in $w$?

Mathematically this is written as:

$$\frac{\partial \mathcal{L}}{\partial w}$$

This notation means: "if I increase $w$ by a tiny amount,
how much does $\mathcal{L}$ change?"

```text
∂L/∂w = +5.2  means: increasing w makes the loss WORSE
                      → we should DECREASE w

∂L/∂w = -3.1  means: increasing w makes the loss BETTER
                      → we should INCREASE w

∂L/∂w = 0.0   means: changing w has no effect on the loss
                      → w does not matter for this prediction
```

---

## 6. The Chain Rule — Why "Back" Propagation

The network is a sequence of functions:

$$\mathcal{L} = f_{\text{loss}}(f_{\text{classifier}}(f_{\text{pool}}(f_{\text{transformer}}(f_{\text{proj}}(\mathbf{X})))))$$

To find $\frac{\partial \mathcal{L}}{\partial w_{\text{proj}}}$
(how the loss depends on one weight in the very first layer),
we must trace through every function in the chain.

This is done using the **chain rule** from calculus:

$$\frac{\partial \mathcal{L}}{\partial w} =
\frac{\partial \mathcal{L}}{\partial z_{\text{last}}}
\cdot
\frac{\partial z_{\text{last}}}{\partial z_{\text{prev}}}
\cdot\ \ldots\ \cdot
\frac{\partial z_{\text{proj}}}{\partial w}$$

In plain English: the gradient at any weight equals the product
of all the gradients of every function that came after it.

This is why the process is called **back**propagation — the
error signal travels **backward** through the network, from
the loss all the way back to the first layer.

```text
Forward pass (left to right):
  X → Projection → CNN → Transformer → Pool → Classifier → Loss

Backward pass (right to left):
  Loss → Classifier → Pool → Transformer → CNN → Projection → X
  
  At each step: compute gradient, pass it further backward
```

---

## 7. The Weight Update — Moving in the Right Direction

Once we have the gradient $\frac{\partial \mathcal{L}}{\partial w}$
for every weight, we update each weight using:

$$w \leftarrow w - \eta \cdot \frac{\partial \mathcal{L}}{\partial w}$$

Where $\eta$ (eta) is the **learning rate** — a small number
like $0.0003$ that controls the step size.

```text
Before update:  w = 0.45
Gradient:       ∂L/∂w = +2.1   (increasing w makes loss worse)
Learning rate:  η = 0.0003

After update:   w = 0.45 - (0.0003 × 2.1)
                w = 0.45 - 0.00063
                w = 0.44937    ← slightly smaller, slightly less wrong
```

This tiny adjustment of 0.00063 seems insignificant. But it
happens for **every one of the 3,772,922 weights** after every
batch of 32 training samples. After 1,169 batches (one epoch),
every weight has been nudged toward producing better predictions.
After 79 epochs, the weights have been nudged 1,169 × 79 = 92,351
times each.

## 8. The Geometry — Loss as a Landscape

A helpful mental model: imagine the loss $\mathcal{L}$ as a
mountainous landscape where:

- Each **horizontal axis** is one weight (there are 3.77M axes —
  impossible to visualise, but imagine 2)
- The **vertical axis** is the loss value
- **Valleys** are where loss is low (good predictions)
- **Peaks** are where loss is high (bad predictions)


![[Pasted image 20260414181841.png]]


At the start of training (random weights), we are somewhere
random on this landscape — probably on a hillside.

The gradient tells us which direction is "uphill."
We move in the **opposite** direction — downhill.

$$w \leftarrow w - \eta \cdot \underbrace{\frac{\partial \mathcal{L}}{\partial w}}_{\text{uphill direction}}$$

This process is called **gradient descent**. Each training step
is a small step downhill. After thousands of steps, we reach
a valley — a configuration of weights that produces low loss
and correct predictions.

## 9. One Complete Training Step — The Full Cycle

```text
┌─────────────────────────────────────────────────────────────┐
│  1. FORWARD PASS                                            │
│     Feed one batch (32 sign sequences) through the network  │
│     Compute predictions: (32, 250) logits                   │
│                                                             │
│  2. LOSS COMPUTATION                                        │
│     Compare 32 predictions to 32 true labels                │
│     Compute average cross-entropy loss: one number L        │
│                                                             │
│  3. BACKWARD PASS (Backpropagation)                         │
│     Compute ∂L/∂w for every weight via chain rule           │
│     Each weight gets its own gradient                       │
│                                                             │
│  4. WEIGHT UPDATE (Gradient Descent)                        │
│     w ← w - η × (∂L/∂w)   for every weight                  │
│     3,772,922 weights updated simultaneously                │
│                                                             │
│  5. REPEAT with the next batch                              │
└─────────────────────────────────────────────────────────────┘
```

This cycle runs 1,169 times per epoch (one pass through all
74,841 training samples). In your Experiment 2, it ran for
79 epochs. Total weight updates:

$$1{,}169 \times 79 = 92{,}351 \text{ updates per weight}$$

$$92{,}351 \times 3{,}772{,}922 \approx 348 \text{ billion individual adjustments}$$

All of this happened in 31 minutes on your RX 7900 XT.

## 10. Why Random Initialisation Works

You might wonder: if all weights start random, how does the
model ever learn anything meaningful?

The key insight is that **the gradient is always informative**
regardless of where the weights start. Even from a random
position on the loss landscape, the gradient always points uphill.
Going downhill always makes the predictions slightly better.

The only requirement is that the starting point is not in a
**flat region** (where gradients are near zero everywhere —
called a saddle point or plateau). This is why weight
initialisation strategies (like Xavier/Glorot initialisation,
which PyTorch uses by default) are designed to place weights in
regions where gradients flow well from the start.

## 11. Connection to Your ASL Project

Every time a batch of 32 sign sequences passes through your model:

```text
The W_proj matrix (88,320 weights) receives gradients like:

∂L/∂W_proj[51, 42] = -0.003
→ "increasing the weight connecting left-shoulder-x to feature-42
   reduces the loss slightly"
→ w[51,42] increases by 0.003 × 0.0003 = 0.0000009

∂L/∂W_proj[0, 7] = +0.091
→ "increasing the weight connecting upper-lip-x to feature-7
   increases the loss"
→ w[0,7] decreases by 0.091 × 0.0003 = 0.0000273
```

After 92,351 such updates, the weight $w[51, 42]$ has learned
to amplify the left shoulder signal for feature 42, and $w[0, 7]$
has learned to suppress the upper-lip signal for feature 7 —
because the data showed that this combination leads to better
sign classification.

Nobody programmed these values. The loss function and 348 billion
gradient updates did.

## 12. Summary

| Concept                                       | One-line definition                                      |
| --------------------------------------------- | -------------------------------------------------------- |
| **Forward pass**                              | Data flows through the network to produce a prediction   |
| **Loss** $\mathcal{L}$                        | One number measuring how wrong the prediction was        |
| **Gradient** $\partial\mathcal{L}/\partial w$ | How much the loss changes if weight $w$ changes          |
| **Chain rule**                                | Gradients multiply through every layer backward          |
| **Backpropagation**                           | Computing all gradients by applying the chain rule       |
| **Gradient descent**                          | $w \leftarrow w - \eta \cdot \nabla w$ — moving downhill |
| **Learning rate** $\eta$                      | Step size — how far to move per update                   |
| **One epoch**                                 | One complete pass through all 74,841 training samples    |

---

## 13. The Equation to Remember

$$\boxed{w \leftarrow w - \eta \cdot \frac{\partial \mathcal{L}}{\partial w}}$$

This single equation, applied 348 billion times to 3,772,922
weights over 79 epochs, is what transformed random numbers into
a model that recognises 250 ASL signs with 43.88% accuracy on
completely unseen signers.
