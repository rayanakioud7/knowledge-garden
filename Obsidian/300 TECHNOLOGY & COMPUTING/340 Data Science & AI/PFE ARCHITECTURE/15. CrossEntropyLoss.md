> **One sentence summary:** CrossEntropyLoss measures how wrong the model's predicted probability distribution is compared to the true label — and gives the gradient signal that drives all 21 million parameters to improve.

---

## 1. Where We Are

After Masked Global Average Pooling, you have:

```text
z  (256,)   ← one summary vector for the entire sign
```

The classification head transforms this into 250 raw scores:

```text
ŷ = W₂ · GELU(W₁z + b₁) + b₂    shape: (250,)
```

Each of these 250 numbers is called a **logit** — a raw unnormalised score. The sign with the highest logit is the model's prediction.

But logits are not probabilities. They can be any real number — positive, negative, large, small. Before we can compare the model's output to the true label, we need to convert them to a proper probability distribution. That is what CrossEntropyLoss does internally.

---

## 2. The Two Steps Inside CrossEntropyLoss

CrossEntropyLoss combines two operations into one:

```text
Step 1:  Softmax   → convert logits to probabilities
Step 2:  NLL Loss  → measure how wrong the probabilities are
```

PyTorch combines them for numerical stability. But understanding them separately makes the concept clear.

---

## 3. Step 1 — Softmax: Logits to Probabilities

**The problem:** The 250 logits are arbitrary real numbers. We need them to be:
- All positive
- Sum to exactly 1.0
- Larger logit → larger probability

**The solution:** Softmax.

$$\hat{p}_c = \frac{e^{\hat{y}_c}}{\displaystyle\sum_{j=1}^{250} e^{\hat{y}_j}} \quad \text{for } c = 1, \ldots, 250$$

The exponential $e^x$ converts any real number to a positive number. Dividing by the sum normalises everything to sum to 1.

### A tiny worked example

Suppose the model produces logits for 4 classes (simplified from 250):

```text
Logits:
  DRINK:   ŷ₁ = 3.2
  MILK:    ŷ₂ = 1.8
  WATER:   ŷ₃ = 0.5
  HELLO:   ŷ₄ = -0.9
```

Step 1: Exponentiate each:

```text
e^3.2  = 24.53
e^1.8  =  6.05
e^0.5  =  1.65
e^-0.9 =  0.41
Sum    = 32.64
```

Step 2: Divide by sum:

```text
p̂(DRINK) = 24.53 / 32.64 = 0.752   (75.2%)
p̂(MILK)  =  6.05 / 32.64 = 0.185   (18.5%)
p̂(WATER) =  1.65 / 32.64 = 0.051   ( 5.1%)
p̂(HELLO) =  0.41 / 32.64 = 0.013   ( 1.3%)
Sum       = 1.000
```

The model is 75.2% confident the sign is DRINK. If the true label is DRINK, this is a good prediction. If the true label is WATER, this is a bad prediction.

But how do we **measure** how bad it is? That is the job of the loss.

---

## 4. Step 2 — Negative Log-Likelihood: Measuring How Wrong

Given the true label $c^*$ (the index of the correct sign), the loss is simply:

$$\mathcal{L} = -\log \hat{p}_{c^*}$$

We take the negative log of the predicted probability for the **correct class only**.

### Why the negative log?

The log function has a critical property:

```text
log(1.0) = 0      ← perfect prediction, zero loss
log(0.5) = -0.69  ← somewhat wrong
log(0.1) = -2.30  ← very wrong
log(0.01) = -4.60 ← extremely wrong
log(0.001) = -6.91 ← catastrophically wrong
```

The negative log of the correct class probability:

```text
-log(1.0) = 0      ← perfect, no loss
-log(0.5) = 0.69   ← somewhat wrong, some loss
-log(0.1) = 2.30   ← very wrong, large loss
-log(0.01) = 4.60  ← extremely wrong, huge loss
```

As the model's confidence in the correct class approaches 1.0, the loss approaches 0. As confidence approaches 0, the loss approaches infinity.

### Back to the DRINK example

**Case 1: True label is DRINK**

$$\mathcal{L} = -\log \hat{p}(\text{DRINK}) = -\log(0.752) = 0.285$$

Small loss. The model is mostly right.

**Case 2: True label is WATER**

$$\mathcal{L} = -\log \hat{p}(\text{WATER}) = -\log(0.051) = 2.976$$

Large loss. The model was very confident about DRINK but the answer was WATER.

**Case 3: True label is DRINK, but model was unsure**

Suppose the logits were flatter and $\hat{p}(\text{DRINK}) = 0.30$:

$$\mathcal{L} = -\log(0.30) = 1.204$$

Moderate loss. The model predicted the correct class but with low confidence.

## 5. The Full CrossEntropyLoss Formula

Combining softmax and negative log-likelihood:

$$\mathcal{L}_{\text{CE}} = -\log \hat{p}_{c^*} = -\log \frac{e^{\hat{y}_{c^*}}}{\sum_{j=1}^{250} e^{\hat{y}_j}}$$

Expanding the log:

$$\mathcal{L}_{\text{CE}} = -\hat{y}_{c^*} + \log \sum_{j=1}^{250} e^{\hat{y}_j}$$

This form is numerically more stable and is what PyTorch actually computes internally.

The two terms have clear interpretations:

| Term | Role |
|------|------|
| $-\hat{y}_{c^*}$ | Reward: push up the logit of the correct class |
| $+\log \sum_j e^{\hat{y}_j}$ | Penalty: push down all logits (to prevent them from growing to infinity) |

The loss is minimised when the correct class logit $\hat{y}_{c^*}$ is much larger than all other logits — exactly what we want.

---

## 6. The Gradient — How the Loss Drives Learning

The whole point of the loss is to produce gradients that update the model parameters.

Taking the derivative of CrossEntropyLoss with respect to the logit $\hat{y}_c$:

$$\frac{\partial \mathcal{L}_{\text{CE}}}{\partial \hat{y}_c} = \hat{p}_c - \mathbf{1}[c = c^*]$$

Where $\mathbf{1}[c = c^*]$ is 1 if $c$ is the correct class and 0 otherwise.

This is a remarkably clean result. For each class:

| Class | Gradient | Effect |
|-------|----------|--------|
| Correct class ($c = c^*$) | $\hat{p}_{c^*} - 1$ | Always negative → push logit UP |
| Wrong class ($c \neq c^*$) | $\hat{p}_c$ | Always positive → push logit DOWN |

**Intuition:**

- The correct class gradient is $\hat{p}_{c^*} - 1$. If the model predicts 75% confidence, gradient = $0.75 - 1 = -0.25$. This negative gradient tells the model to increase the DRINK logit.
- Every wrong class gets a positive gradient proportional to how much probability it was assigned. If the model gave 18.5% to MILK when the answer was DRINK, the MILK logit gets pushed down by 0.185.

The gradients are larger when the model is more wrong. A prediction of 1% on the correct class produces a gradient of $0.01 - 1 = -0.99$ — a strong signal to correct itself. A prediction of 99% produces a gradient of $0.99 - 1 = -0.01$ — almost no update needed.

This is the **self-calibrating** property of CrossEntropyLoss. The stronger the error, the stronger the correction.

---

## 7. Over a Full Batch

In practice, you compute the loss over a batch of $B = 64$ samples and average:

$$\mathcal{L} = \frac{1}{B} \sum_{i=1}^{B} \mathcal{L}^{(i)}_{\text{CE}} = -\frac{1}{B} \sum_{i=1}^{B} \log \hat{p}^{(i)}_{c^*_i}$$

Where $c^*_i$ is the true label for sample $i$ in the batch.

In your training loop:

```python
criterion = nn.CrossEntropyLoss(label_smoothing=0.1)
logits    = model(batch_X)          # (64, 250)
loss      = criterion(logits, batch_y)  # scalar
loss.backward()                     # compute gradients
optimizer.step()                    # update all parameters
```

`nn.CrossEntropyLoss` in PyTorch:
- Accepts raw logits (not softmax outputs)
- Applies log-softmax internally (numerically stable)
- Averages over the batch automatically
- Takes integer class indices as targets (not one-hot vectors)

## 8. Why Not Use Mean Squared Error?

A natural question: why not just use:

$$\mathcal{L}_{\text{MSE}} = \frac{1}{250} \sum_{c=1}^{250} (p_c - \hat{p}_c)^2$$

Where $p_c = 1$ for the correct class and 0 for all others?

**Three reasons CrossEntropy is better:**

### Reason 1: Gradient magnitude

MSE gradient for the correct class:

$$\frac{\partial \mathcal{L}_{\text{MSE}}}{\partial \hat{p}_{c^*}} = 2(\hat{p}_{c^*} - 1)$$

At $\hat{p}_{c^*} = 0.99$ (almost perfect): gradient = $2(0.99-1) = -0.02$ — very small, good.
At $\hat{p}_{c^*} = 0.01$ (very wrong): gradient = $2(0.01-1) = -1.98$ — strong, good.

But MSE operates on probabilities which are squashed by softmax. The gradient through softmax is small for extreme values. CrossEntropy avoids this by operating on logits directly.

### Reason 2: Probabilistic interpretation

CrossEntropyLoss has a direct probabilistic interpretation: it minimises the Kullback-Leibler divergence between the true label distribution and the predicted distribution. This is the mathematically correct objective for classification.

MSE treats classification as a regression problem — it tries to minimise the squared distance to a target vector. This is mathematically incorrect for probability distributions.

### Reason 3: Speed of learning

When the model is very wrong (predicts 1% on the correct class), CrossEntropy gradient is $0.01 - 1 = -0.99$ — very strong correction.

MSE gradient at the same point is approximately $-1.98$ through the probabilities but much smaller through the logits after the softmax Jacobian. In practice, CrossEntropy learns faster on classification problems.

## 9. Label Smoothing — The Version Your Model Actually Uses

Your model does not use pure CrossEntropyLoss. It uses **label smoothing** with $\epsilon = 0.1$.

### The problem with hard labels

Standard CrossEntropyLoss trains toward:

$$\mathbf{p}_{\text{true}} = [0, 0, \ldots, 1, \ldots, 0]$$

All probability on one class, zero on all others. The model is incentivised to push the correct class logit toward $+\infty$ — which is impossible and leads to overconfident predictions that generalise poorly.

### What label smoothing does

Instead of training toward the one-hot vector, label smoothing trains toward a softer distribution:

$$\tilde{p}_c = \begin{cases} 1 - \epsilon + \dfrac{\epsilon}{250} & \text{if } c = c^* \\ \dfrac{\epsilon}{250} & \text{if } c \neq c^* \end{cases}$$

With $\epsilon = 0.1$ and 250 classes:

$$\tilde{p}_{c^*} = 1 - 0.1 + \frac{0.1}{250} = 0.9004$$

$$\tilde{p}_{c \neq c^*} = \frac{0.1}{250} = 0.0004$$

Instead of training toward $[0, 0, \ldots, 1, \ldots, 0]$, the model trains toward $[0.0004, 0.0004, \ldots, 0.9004, \ldots, 0.0004]$.

### The smoothed loss formula

$$\mathcal{L}_{\text{smooth}} = -\sum_{c=1}^{250} \tilde{p}_c \log \hat{p}_c$$

Expanding:

$$\mathcal{L}_{\text{smooth}} = -\tilde{p}_{c^*} \log \hat{p}_{c^*} - \sum_{c \neq c^*} \tilde{p}_c \log \hat{p}_c$$

$$= -(1-\epsilon)\log \hat{p}_{c^*} - \frac{\epsilon}{250} \sum_{c=1}^{250} \log \hat{p}_c$$

The first term is the standard CrossEntropy. The second term is the entropy of the uniform distribution — it pulls all predicted probabilities toward $\frac{1}{250}$.

### What this achieves in your model

Two concrete benefits for signer-independent evaluation:

**Benefit 1: Prevents overconfident predictions**

Without smoothing, the model might predict DRINK with 99.9% confidence on training signers. When it sees a new signer, the same hand position might look slightly different and the model still assigns 99.9% — incorrectly.

With smoothing, the model is never incentivised to go beyond 90% confidence. It stays in a regime where the 250-class probability distribution is informative.

**Benefit 2: Better calibration**

Error analysis on your production model confirmed ECE = 0.097 with no temperature scaling. When the model says 82%, it is correct 82.5% of the time. This calibration emerges naturally from label smoothing.

### A worked example with smoothing

True label: DRINK ($c^* = $ index of DRINK in 250 classes)

```sql
Without smoothing, target distribution:
  DRINK: 1.0000
  all others: 0.0000

With label smoothing (ε=0.1, 250 classes):
  DRINK: 0.9004
  MILK:  0.0004
  WATER: 0.0004
  ... (all 249 other classes): 0.0004
```

The model now gets a small gradient signal to not completely ignore the other 249 classes. This prevents the model from confidently mapping "anything that looks like a wrist moving toward the mouth" to DRINK — it must preserve some uncertainty.

## 10. What the Loss Value Actually Means

After training converges, what does a loss of, say, 2.2 mean?

**Random baseline:**
If the model predicts uniformly (1/250 = 0.004 for each class):

$$\mathcal{L}_{\text{random}} = -\log\!\left(\frac{1}{250}\right) = \log(250) \approx 5.52$$

**Perfect prediction:**
If the model always predicts 100% on the correct class:

$$\mathcal{L}_{\text{perfect}} = -\log(1.0) = 0$$

**Your model's training loss (Experiment 11, best epoch 79):**

$$\mathcal{L}_{\text{train}} \approx 0.89$$

This means the model assigns an average of $e^{-0.89} \approx 41\%$ probability to the correct class on training data — reasonable given 250 classes and label smoothing capping the ceiling.

**Your model's validation loss (Experiment 11, best epoch 79):**

$$\mathcal{L}_{\text{val}} \approx 2.37$$

This means the model assigns an average of $e^{-2.37} \approx 9.4\%$ probability to the correct class on validation data. With 250 classes, 9.4% is about 23× better than random (0.4%). The gap between training loss and validation loss reflects the generalisation challenge of signer-independent evaluation.

## 11. CrossEntropy and the 250-Class Problem

With 250 classes, CrossEntropyLoss has a specific challenge: the model must distinguish between signs that are linguistically very similar (awake/wake, cut/scissors, hear/listen).

The loss does not know about linguistic similarity. It treats every wrong class identically — predicting MILK when the answer is DRINK incurs exactly the same loss as predicting HELLO when the answer is DRINK.

This is both a strength and a weakness:

**Strength:** The model is forced to find discriminative features for every pair of signs, even similar ones.

**Weakness:** The model cannot communicate "I was almost right" — predicting MILK when the answer is DRINK is treated identically to a completely wrong prediction.

Label smoothing partially addresses this by softening the hard boundary — the model is never penalised infinitely for assigning a tiny probability to wrong classes.

## 12. The Training Loop — Complete Picture

Now you can see how all the pieces connect:

```text
For each batch of 64 signs:

1. Forward pass:
   X (64, 64, 690)          ← batch of 64 sign sequences
       ↓ Linear projection
   H⁰ (64, 64, 256)
       ↓ CNN block
   H¹ (64, 64, 256)
       ↓ Positional encoding
   H² (64, 64, 256)
       ↓ 4 (or 6) Transformer layers
   H^L (64, 64, 256)
       ↓ Masked GAP
   z  (64, 256)
       ↓ Classification head
   ŷ  (64, 250)             ← 250 logits per sign

2. Loss computation:
   L = CrossEntropyLoss(ŷ, y_true)   ← scalar

3. Backward pass:
   ∂L/∂ŷ   → (64, 250) gradient of loss w.r.t. logits
   ∂L/∂z   → (64, 256) backprop through classifier
   ∂L/∂H^L → (64, 64, 256) backprop through Transformer
   ...all the way back to W_proj...

4. Update:
   θ ← θ - η · ∇_θ L    (AdamW handles this)
```

The CrossEntropyLoss is the single scalar at the centre of this entire operation. Everything before it is the forward pass producing the prediction. Everything after it is the backward pass propagating corrections.

## 13. Summary

| Concept | Definition |
|---------|------------|
| **Logit** | Raw unnormalised score for one class — any real number |
| **Softmax** | Converts 250 logits to a probability distribution summing to 1 |
| **NLL Loss** | $-\log \hat{p}_{c^*}$ — negative log probability of the correct class |
| **CrossEntropyLoss** | Softmax + NLL combined — operates on logits directly |
| **Loss = 0** | Model predicts 100% confidence on the correct class |
| **Loss = 5.52** | Model predicts randomly (uniform over 250 classes) |
| **Gradient** | $\hat{p}_c - \mathbf{1}[c = c^*]$ — push correct class up, wrong classes down |
| **Label smoothing** | Replaces hard targets with soft distribution — prevents overconfidence |
| **$\epsilon = 0.1$** | 90.04% on correct class, 0.04% on each wrong class |
| **ECE = 0.097** | Your model's calibration — confidence tracks accuracy well |

## 14. The Full Equation — Every Symbol Explained

### Standard CrossEntropyLoss:

$$\boxed{\mathcal{L}_{\text{CE}} = -\log \frac{e^{\hat{y}_{c^*}}}{\displaystyle\sum_{j=1}^{250} e^{\hat{y}_j}} = -\hat{y}_{c^*} + \log \sum_{j=1}^{250} e^{\hat{y}_j}}$$

### With label smoothing (what your model uses):

$$\boxed{\mathcal{L}_{\text{smooth}} = -(1-\epsilon)\log \hat{p}_{c^*} - \frac{\epsilon}{250}\sum_{c=1}^{250}\log \hat{p}_c}$$

| Symbol | Meaning |
|--------|---------|
| $\hat{y}_c$ | Logit for class $c$ — raw output of classifier head |
| $c^*$ | True class index (correct ASL sign) |
| $\hat{p}_c = \frac{e^{\hat{y}_c}}{\sum_j e^{\hat{y}_j}}$ | Predicted probability for class $c$ after softmax |
| $\epsilon = 0.1$ | Label smoothing parameter |
| $(1-\epsilon) = 0.9$ | Weight on correct class |
| $\frac{\epsilon}{250} = 0.0004$ | Small weight distributed to all wrong classes |

## 15. What Comes Next

CrossEntropyLoss gives you a scalar $\mathcal{L}$ and its gradients $\frac{\partial \mathcal{L}}{\partial \hat{y}_c}$.

Those gradients flow backwards through the entire model — through the classifier, through GAP, through the Transformer layers, through the CNN, through the linear projection — updating all 21 million parameters.

The mechanism that uses those gradients to update the parameters is the **optimiser**.

That is concept 17: **AdamW** — how the weights actually update.
