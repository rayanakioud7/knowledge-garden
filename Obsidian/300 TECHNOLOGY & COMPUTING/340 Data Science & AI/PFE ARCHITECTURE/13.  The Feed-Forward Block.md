
---

> **One sentence summary:** The feed-forward block takes each frame's representation after attention and runs it through a two-layer neural network independently — giving the model a chance to think deeply about each frame on its own, after it has already gathered information from all other frames.

---

## 1. Where We Are in the Pipeline

After multi-head attention, each frame has been enriched with global context. Frame 20 now knows what frame 5 and frame 40 are doing. The representation has changed shape from input to output of attention:

```
Input to attention:   H² (64, 256)   ← each frame is 256-dimensional
Output of attention:  Z  (64, 256)   ← same shape, richer content
```

But attention is fundamentally a **mixing** operation. It combines information from different frames. It does not deeply **process** any single frame's representation on its own.

The feed-forward block does the opposite: it takes each frame and thinks about it **independently**, with no communication between frames.

```
Attention:      every frame talks to every other frame
Feed-forward:   every frame thinks for itself
```

Together they are complementary. The Transformer alternates between these two operations in every layer.

---

## 2. The Intuition — A Two-Step Thought Process

Imagine you are a linguist watching a sign video.

**Step 1 — Attention:** You watch all 64 frames simultaneously and take notes about which frames are related. "Frame 5 is the preparation. Frame 20 is the core sign. Frame 40 is the retraction."

**Step 2 — Feed-forward:** You now sit down with your notes about frame 20 and think deeply: "Given everything I know about frame 20 and its relationship to the other frames, what does this actually MEAN? Is this consistent with the DRINK sign? Or could it be MILK? What non-linear features do I need to compute to answer this?"

The feed-forward block is the deep thinking step. Attention gathers information. Feed-forward processes it.

---

## 3. The Architecture — Two Linear Layers with GELU

The feed-forward block (also called the position-wise feed-forward network, or FFN) is a simple two-layer MLP:

$$\text{FFN}(\mathbf{x}) = \mathbf{W}_2 \cdot \text{GELU}(\mathbf{W}_1 \mathbf{x} + \mathbf{b}_1) + \mathbf{b}_2$$

Where:

| Symbol | Shape | What it is |
|--------|-------|------------|
| $\mathbf{x}$ | $(256,)$ | One frame's representation after attention |
| $\mathbf{W}_1$ | $(256, 1024)$ | First weight matrix — expands dimension |
| $\mathbf{b}_1$ | $(1024,)$ | First bias |
| $\text{GELU}(\cdot)$ | $(1024,)$ | Non-linearity applied element-wise |
| $\mathbf{W}_2$ | $(1024, 256)$ | Second weight matrix — compresses back |
| $\mathbf{b}_2$ | $(256,)$ | Second bias |
| $\text{FFN}(\mathbf{x})$ | $(256,)$ | Processed frame representation |

Input dimension: **256**
Hidden dimension: **1024** (4× expansion)
Output dimension: **256** (back to original)

This is applied independently to each of the 64 frames. Not to the sequence as a whole. Not to all frames at once. Each frame goes through its own FFN computation with the same weights but its own input vector.

---

## 4. The $4\times$ Expansion — Why?

The hidden dimension is always $4 \times d_{\text{model}}$. In your base model:

$$d_{\text{ff}} = 4 \times d_{\text{model}} = 4 \times 256 = 1{,}024$$

In your scaled model (Experiment 10 and 11):

$$d_{\text{ff}} = 4 \times 512 = 2{,}048$$

**Why $4\times$?**

The first linear layer expands the representation from 256 dimensions to 1024 dimensions. In this higher-dimensional space the model has more room to compute complex non-linear transformations of the frame's features.

Think of it this way. You have a 256-dimensional description of what is happening at frame 20. You want to compute all the non-linear interactions between those 256 features — velocity cross-correlated with hand position, handshape interacting with facial expression, etc. Projecting to 1024 dimensions gives you 1024 neurons to detect all those combinations. Then you compress back to 256.

The $4\times$ ratio comes from the original Transformer paper (Vaswani et al. 2017) and has remained standard because it works well empirically across almost all Transformer applications.

## 5. Step-by-Step Computation

Let us trace one frame through the entire FFN.

**Setup:** Frame 20 after attention, $\mathbf{z}_{20} \in \mathbb{R}^{256}$

```
z₂₀ = [0.42, -0.18, 0.91, 0.03, ..., -0.55]   (256 values)
```

### Step 1: First linear layer — expand to 1024

$$\mathbf{h} = \mathbf{W}_1 \mathbf{z}_{20} + \mathbf{b}_1$$

$$\underbrace{(1024, 256)}_{\mathbf{W}_1} \times \underbrace{(256,)}_{\mathbf{z}_{20}} + \underbrace{(1024,)}_{\mathbf{b}_1} = \underbrace{(1024,)}_{\mathbf{h}}$$

Each of the 1024 output neurons computes a weighted sum of all 256 input features plus a bias. This is a linear combination:

$$h_j = \sum_{i=1}^{256} W_1[j, i] \cdot z_{20,i} + b_1[j] \quad \text{for } j = 1 \ldots 1024$$

At this point the computation is still linear. Nothing interesting has happened yet.

### Step 2: GELU activation — introduce non-linearity

$$\mathbf{h}' = \text{GELU}(\mathbf{h})$$

Applied element-wise to each of the 1024 values.

Without this step the entire FFN would collapse to a single linear transformation — two linear layers in sequence are equivalent to one linear layer. The activation function is what gives the FFN its expressive power.

We will cover GELU in detail below (Section 6).

### Step 3: Second linear layer — compress back to 256

$$\text{FFN}(\mathbf{z}_{20}) = \mathbf{W}_2 \mathbf{h}' + \mathbf{b}_2$$

$$\underbrace{(256, 1024)}_{\mathbf{W}_2} \times \underbrace{(1024,)}_{\mathbf{h}'} + \underbrace{(256,)}_{\mathbf{b}_2} = \underbrace{(256,)}_{\text{output}}$$

The 1024-dimensional activated representation is compressed back to 256. The model has selected which of the 1024 computed features are actually useful and mixed them back into the 256-dimensional space.

## 6. GELU — Why Not ReLU?

You learned about activation functions in concept 5. The FFN in your model uses **GELU** (Gaussian Error Linear Unit) instead of the more common ReLU.

### ReLU reminder

$$\text{ReLU}(x) = \max(0, x)$$

If $x > 0$: pass through unchanged.
If $x \leq 0$: set to zero.

### GELU definition

$$\text{GELU}(x) = x \cdot \Phi(x)$$

Where $\Phi(x)$ is the cumulative distribution function (CDF) of the standard normal distribution:

$$\Phi(x) = P(X \leq x) \quad \text{where } X \sim \mathcal{N}(0, 1)$$

In practice, a fast approximation is used:

$$\text{GELU}(x) \approx 0.5 \cdot x \cdot \left(1 + \tanh\!\left(\sqrt{\frac{2}{\pi}}\left(x + 0.044715 x^3\right)\right)\right)$$

### What GELU looks like

```
x:       -3    -2    -1     0    0.5    1     2     3
ReLU:     0     0     0     0    0.5    1     2     3
GELU:  -0.004 -0.046 -0.159 0  0.346  0.841  1.954  2.996
```

### The critical difference

**ReLU is binary:** a neuron is either completely on (identity) or completely off (zero). There is a hard cliff at $x = 0$.

**GELU is smooth:** a neuron with value $x = -0.5$ is not completely zeroed out — it passes through about $-0.09$ (33% of its value). A neuron with $x = 0.5$ passes through about $0.35$ (69% of its value). The transition is smooth.

### Why this matters for Transformers

The hard cutoff in ReLU creates **dead neurons** — neurons that get stuck at exactly zero and stop receiving gradient signal. This is more problematic in deep models.

The smooth gradient of GELU means every neuron always receives some gradient signal, even small negative values. This produces more stable training for deep Transformer architectures.

GELU was introduced by Hendrycks & Gimpel (2016) and has become the standard for Transformers. GPT, BERT, and your model all use GELU in the FFN.

## 7. Position-Wise — What This Actually Means

The FFN is described as **position-wise** in the original Transformer paper. This is a key word.

Position-wise means: the same function is applied to each position (each frame) independently, with the same weights.

```
Frame 1  → FFN(z₁)  using W₁, W₂
Frame 2  → FFN(z₂)  using W₁, W₂  ← same weights
Frame 20 → FFN(z₂₀) using W₁, W₂  ← same weights
Frame 64 → FFN(z₆₄) using W₁, W₂  ← same weights
```

All 64 frames use the same $\mathbf{W}_1$ and $\mathbf{W}_2$. The only difference is the input vector.

**This is different from attention**, which processes all 64 frames simultaneously as one matrix operation.

In terms of computation, the position-wise FFN applied to all 64 frames at once is:

$$\text{FFN}(\mathbf{Z}) = \text{GELU}(\mathbf{Z}\mathbf{W}_1 + \mathbf{b}_1)\mathbf{W}_2 + \mathbf{b}_2$$

$$\underbrace{(64, 256)}_{\mathbf{Z}} \times \underbrace{(256, 1024)}_{\mathbf{W}_1} = \underbrace{(64, 1024)}_{\text{hidden}}$$

$$\underbrace{(64, 1024)}_{\text{GELU applied}} \times \underbrace{(1024, 256)}_{\mathbf{W}_2} = \underbrace{(64, 256)}_{\text{output}}$$

Efficient. Parallelisable across all 64 frames simultaneously.

## 8. A Tiny Worked Example

Let us use small dimensions to make this concrete.
Suppose $d_{\text{model}} = 4$ and $d_{\text{ff}} = 8$ (2× for simplicity instead of 4×).

**Input:** $\mathbf{z}_{20} = [1.2, -0.5, 0.8, 0.3]$

**Weight matrix $\mathbf{W}_1$ (8×4):**

```
W₁ = [[ 0.3,  0.1, -0.2,  0.5],
      [-0.4,  0.7,  0.1, -0.3],
      [ 0.2, -0.1,  0.6,  0.4],
      [ 0.8,  0.2, -0.5,  0.1],
      [-0.1,  0.4,  0.3, -0.6],
      [ 0.5, -0.3,  0.2,  0.7],
      [-0.2,  0.6, -0.4,  0.2],
      [ 0.4, -0.8,  0.5, -0.1]]
```

**Step 1:** $\mathbf{h} = \mathbf{W}_1 \mathbf{z}_{20}$ (ignoring bias for clarity)

```
h₁ = 0.3×1.2 + 0.1×(-0.5) + (-0.2)×0.8 + 0.5×0.3
   = 0.36 - 0.05 - 0.16 + 0.15 = 0.30

h₂ = (-0.4)×1.2 + 0.7×(-0.5) + 0.1×0.8 + (-0.3)×0.3
   = -0.48 - 0.35 + 0.08 - 0.09 = -0.84

... (computed for all 8 neurons)

h = [0.30, -0.84, 0.76, 0.69, -0.51, 0.89, -0.42, 0.23]
```

**Step 2:** Apply GELU element-wise

```
GELU(0.30)  ≈ 0.185   (positive, mostly passes through)
GELU(-0.84) ≈ -0.101  (negative, mostly suppressed)
GELU(0.76)  ≈ 0.576   (positive, passes through)
GELU(0.69)  ≈ 0.508   (positive, passes through)
GELU(-0.51) ≈ -0.074  (negative, mostly suppressed)
GELU(0.89)  ≈ 0.706   (positive, passes through)
GELU(-0.42) ≈ -0.059  (negative, mostly suppressed)
GELU(0.23)  ≈ 0.131   (positive, partly suppressed)

h' = [0.185, -0.101, 0.576, 0.508, -0.074, 0.706, -0.059, 0.131]
```

**Step 3:** $\mathbf{W}_2 \mathbf{h}'$ compresses back to 4 dimensions.

The negative values from GELU contribute small negative amounts. The positive values contribute larger amounts. The final 4-dimensional output is a non-linear transformation of the original input.

## 9. What Does the FFN Actually Learn?

The weight matrix $\mathbf{W}_1$ learns to detect patterns in the 256-dimensional frame representation. Each of the 1024 neurons in the hidden layer computes one specific linear combination of the 256 input features.

After GELU, only neurons that are strongly activated (large positive values) significantly influence the output. Neurons with large negative values are suppressed.

**Concretely in your ASL project:**

After training, certain neurons in $\mathbf{W}_1$ might specialise in detecting:

```
Neuron 42:  high activation when  (left wrist y-velocity > 0.3)
              AND (right hand x-position > 0.4)
              "hand moving upward and to the right simultaneously"

Neuron 187: high activation when  (eyebrow position < -0.2)
              AND (mouth is open)
              "furrowed brows + open mouth" (wh-question marker in ASL)

Neuron 613: high activation when  (velocity block entries ≈ 0)
              "the frame is nearly static"
              → likely padding or retraction phase
```

None of these were programmed. They emerge from 421 minutes of gradient descent on 212,000 training sequences.

## 10. The Residual Connection Around FFN

Just like after attention, the FFN is wrapped in a **residual connection** and **LayerNorm**.

In your model (Pre-LN style, `norm_first=True`):

$$\text{output} = \mathbf{z} + \text{FFN}(\text{LayerNorm}(\mathbf{z}))$$

Where $\mathbf{z}$ is the output of the attention block (already with its own residual connection applied).

Breaking this down:

```
z           (64, 256)   ← attention output with residual
LayerNorm(z)(64, 256)   ← normalise before FFN
FFN(...)    (64, 256)   ← two-layer MLP
z + FFN(...)(64, 256)   ← add residual
```

**Why the residual connection matters here:**

The FFN might not improve every frame's representation. For some frames the original attention output $\mathbf{z}$ is already good enough. The residual connection allows the FFN to output approximately zero (a small perturbation) for those frames, effectively being bypassed. Only frames that need deeper processing receive significant modification.

This is the same argument from concept 9 (Residual Connection) applied here.

## 11. One Complete Transformer Layer — The Full Picture

Now you have all the pieces. One Transformer encoder layer = attention + FFN, each with residual + LayerNorm.

In Pre-LN style (your model):

```
Input: x  (64, 256)
│
├── LayerNorm(x)                    normalise
│       ↓
├── MultiHeadAttention(...)          attend to all frames
│       ↓
├── x + attention_output            residual connection 1
│       ↓  (call this x')
├── LayerNorm(x')                   normalise again
│       ↓
├── FFN(...)                        process each frame independently
│       ↓
└── x' + ffn_output                 residual connection 2
        ↓
     Output: (64, 256)
```

Your base model has 4 of these layers stacked.
Your scaled model (Experiments 10 and 11) has 6.

Each layer refines the frame representations:
- Attention: global context (connect all frames)
- FFN: local processing (think deeply about each frame)
- Residual: preserve what was already good
- LayerNorm: keep values in a stable range

---

## 12. Shape Transformations — Complete FFN View

```
After attention:
  z  (64, 256)

LayerNorm:
  (64, 256)   → values stabilised per frame

First linear layer (W₁: 256→1024):
  (64, 256) × (256, 1024) = (64, 1024)

GELU:
  (64, 1024)   → non-linearity applied element-wise

Second linear layer (W₂: 1024→256):
  (64, 1024) × (1024, 256) = (64, 256)

Residual:
  (64, 256) + (64, 256) = (64, 256)

Output: (64, 256)   ← same shape, richer representation
```

The FFN never changes the shape. Input and output are always $(64, 256)$ in the base model or $(64, 512)$ in the scaled model.

## 14. Why Is the FFN So Important?

A common misconception is that attention is the most important part of the Transformer. Research suggests the FFN stores more learned knowledge.

Evidence from mechanistic interpretability studies:

- When you **ablate** (remove) attention layers, performance drops but the model can still classify roughly
- When you **ablate** FFN layers, performance collapses completely

One interpretation: attention decides **where** to look, the FFN decides **what to do** with what it saw.

In your ASL project:
- Attention learns which frames are related to which other frames
- FFN learns the feature detectors that map frame representations to sign class evidence

Both are essential. Neither alone is sufficient.

## 15. Summary

| Concept | Definition |
|---------|------------|
| **FFN** | Two-layer MLP applied independently to each frame |
| **$d_{\text{ff}}$** | Hidden dimension = $4 \times d_{\text{model}}$ |
| **Expand** | $\mathbf{W}_1$: $256 \rightarrow 1024$ — more room for non-linear computation |
| **GELU** | Smooth activation — avoids dead neurons, better gradients |
| **Compress** | $\mathbf{W}_2$: $1024 \rightarrow 256$ — select useful features |
| **Position-wise** | Same weights for every frame — applied independently |
| **Residual** | Add input back — model can bypass FFN if not needed |
| **Purpose** | Deep per-frame processing after global context from attention |

## 16. The Full Equation — Every Symbol Explained

$$\boxed{\text{FFN}(\mathbf{x}) = \mathbf{W}_2 \cdot \text{GELU}(\mathbf{W}_1 \mathbf{x} + \mathbf{b}_1) + \mathbf{b}_2}$$

| Symbol | Shape | What it does |
|--------|-------|--------------|
| $\mathbf{x}$ | $(256,)$ | One frame's attended representation |
| $\mathbf{W}_1$ | $(256, 1024)$ | Expands to higher-dimensional space |
| $\mathbf{b}_1$ | $(1024,)$ | Bias for expansion |
| $\text{GELU}(\cdot)$ | $(1024,)$ | Smooth non-linearity |
| $\mathbf{W}_2$ | $(1024, 256)$ | Compresses back to model dimension |
| $\mathbf{b}_2$ | $(256,)$ | Bias for compression |
| $\text{FFN}(\mathbf{x})$ | $(256,)$ | Deeply processed frame representation |

Applied to all 64 frames simultaneously via matrix multiplication:

$$\text{FFN}(\mathbf{Z}) = \text{GELU}(\mathbf{Z}\mathbf{W}_1 + \mathbf{b}_1)\mathbf{W}_2 + \mathbf{b}_2$$

$$\underbrace{(64, 256)}_{\mathbf{Z}} \rightarrow \underbrace{(64, 1024)}_{\text{expand}} \rightarrow \underbrace{(64, 1024)}_{\text{GELU}} \rightarrow \underbrace{(64, 256)}_{\text{compress}}$$

## 17. What Comes Next

After the FFN and its residual connection, you have completed one full Transformer encoder layer:

```
One encoder layer:
  Attention (global context)   → residual + LN
  FFN       (per-frame depth)  → residual + LN
  Output:   (64, 256)
```

Your model stacks 4 (base) or 6 (scaled) of these layers.

After all layers complete, the output is $(64, 256)$ — 64 frame representations, each enriched by:
- 4 (or 6) rounds of global attention
- 4 (or 6) rounds of deep per-frame processing
- Residual connections preserving all previous information

The next step is to collapse these 64 frames into a single vector for classification.

That is concept 14: **Global Average Pooling**.
